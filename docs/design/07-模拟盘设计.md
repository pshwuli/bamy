BAMY 模拟盘设计

本文档是 BAMY 框架的第七份设计文档，定义：模拟盘是什么、怎么运作、撮合规则、手续费、滑点、净值快照、多盘对比、与实盘的隔离、与实盘的一致性保证、插件在模拟盘的生效方式。
不写代码，只写规则和逻辑。本文档是完整设计，不是第一版，是最终态。

二、模拟盘是什么

2.1 定义

模拟盘 = 用虚拟资金跑真实策略，行情是真的，成交是本地撮合的。

它是 BAMY 里用于验证策略、对比策略、避免实盘风险的一种运行模式。

2.2 模拟盘不是什么

· 模拟盘不是回测。回测是历史行情，模拟盘是实时行情。
· 模拟盘不是沙盘。模拟盘用真实行情，是实时的。
· 模拟盘不是实盘的影子。模拟盘有独立的资金、独立的持仓、独立的订单。

2.3 模拟盘在系统中的位置

```
实例（paper=true）
  ├── 行情：从行情中心拿（真实）
  ├── 策略：和实盘同一个策略包
  ├── 订单：不发给币安，发给模拟撮合引擎
  ├── 资金：虚拟，独立
  ├── 持仓：虚拟，独立
  └── 记录：和实盘同一套表
```

2.4 模拟盘和实盘的关系

模拟盘和实盘只差一个地方：下单那一步走币安还是走本地。

其他全一样：

· 一样的策略代码
· 一样的参数
· 一样的订单记录表
· 一样的对账逻辑（模拟盘对的是本地账户）
· 一样的事件总线
· 一样的日志
· 一样的审计

策略代码完全不知道自己跑在模拟还是实盘——它只知道调 ctx.buy。

三、模拟盘和实盘的区别

3.1 完整对比表

维度 实盘 模拟盘
账号绑定 必须绑账号 不绑账号
资金 币安真实余额 虚拟初始资金
持仓 币安真实持仓 本地虚拟持仓
订单 发给币安 本地撮合
行情 共享行情中心 共享行情中心
策略 同一个策略包 同一个策略包
参数 同一套 schema 同一套 schema
手续费 币安实收 按配置模拟
滑点 币安实际 按配置模拟
对账 与币安对账 与本地账户对账
风控 同一套 同一套
保护 挂币安 本地跟踪
日志 同一套 同一套
审计 同一套 同一套
分享 可分享 可分享
快照 可选（从余额推算） 必须（本地生成）

3.2 关键区别

区别 1：订单路径

· 实盘：订单中心 → 连接池 → 币安
· 模拟盘：订单中心 → 模拟撮合引擎 → 本地

区别 2：持仓来源

· 实盘：从币安拉取
· 模拟盘：本地维护

区别 3：资金

· 实盘：币安余额
· 模拟盘：本地虚拟余额

区别 4：对账

· 实盘：与币安对账
· 模拟盘：本地自查（一致性检查）

3.3 完全相同的部分

· 行情：共享
· 策略：共享
· 参数：共享
· 订单记录：共享表
· 日志：共享
· 审计：共享
· 风控：共享
· 保护机制：共享（保护单在模拟盘是本地跟踪）
· 事件总线：共享
· 实例生命周期：共享

"共享"意味着：模拟盘和实盘用同一套代码、同一套表、同一套逻辑，只有"下单"这一步分叉。

四、模拟盘的账户

4.1 账户结构

每个模拟实例有一个独立的模拟账户：

字段 说明
instance_id 所属实例
balance USDT 余额
positions 持仓（symbol -> 数量）
avg_price 均价（symbol -> 价格）
realized_pnl 已实现盈亏
unrealized_pnl 未实现盈亏
equity 净值
initial_balance 初始资金
peak_equity 高水位净值
created_at 创建时间
updated_at 更新时间

4.2 账户创建

· 模拟实例首次启动时创建账户
· 初始资金从实例的 paper_balance 读
· 后续启动复用已有账户（除非用户手动重置）
· 账户 ID = 实例 ID（一一对应）

4.3 账户重置

用户可以重置模拟账户：

· 清空持仓
· 清空挂单
· 余额恢复为初始资金
· 记录审计
· 只能在实例停止时重置

4.4 账户持久化

· 账户数据落库（模拟盘不像实盘那样可以随时从币安拉）
· 每次成交后立即写库
· 每个快照周期也写库
· 进程重启后从库恢复

4.5 账户的隔离

· 每个模拟实例一个独立账户
· 账户之间完全隔离
· 不同实例的模拟盘不共享资金
· 不同用户的模拟盘不共享任何东西

五、模拟盘怎么撮合

5.1 撮合的定义

撮合 = 把订单变成成交的过程。 模拟盘的撮合在本地完成，不经过币安。

5.2 撮合的输入

· 订单：方向、类型、数量、价格
· 行情：当前 last、bid、ask
· 账户：余额、持仓
· 配置：手续费、滑点、成交模式

5.3 撮合的输出

· 成交：成交价、成交量
· 手续费：扣除
· 滑点：已计入成交价
· 账户变更：余额、持仓
· 订单状态：filled / partial / rejected

5.4 撮合的时机

· 市价单：立即撮合
· 限价单（立即成交模式）：立即检查是否可成交
· 限价单（挂单簿模式）：进挂单簿，价格触及才成交
· 止损单：价格触及才触发
· 止盈单：价格触及才触发

5.5 撮合的规则

规则 1：市价单

· 成交价 = last / bid / ask（可配）
· 立即成交
· 状态置 filled

规则 2：限价单（立即成交模式）

· 买单：如果 limit_price >= ask → 立即成交，成交价 = ask
· 买单：如果 limit_price < ask → 挂单（或拒绝，取决于配置）
· 卖单：如果 limit_price <= bid → 立即成交，成交价 = bid
· 卖单：如果 limit_price > bid → 挂单（或拒绝）

规则 3：限价单（挂单簿模式）

· 进挂单簿
· 每次 tick 检查是否可成交
· 可成交 → 成交
· 用户可撤单

规则 4：止损单

· 价格触及 stop_price → 转市价单
· 立即成交

规则 5：止盈单

· 价格触及 take_profit_price → 转市价单
· 立即成交

5.6 撮合的优先级

· 同一 tick 内，按订单创建时间排序
· 先创建的先撮合
· 避免同一 tick 内的不公平

5.7 撮合的拒绝

以下情况拒绝：

· 余额不足（买单）
· 持仓不足（卖单）
· 参数非法
· 超过单笔限额

拒绝时：

· 订单状态置 rejected
· 记录原因
· 不改变账户

六、手续费怎么算

6.1 手续费配置

每个模拟实例可以配置：

配置 默认 说明
fee_rate 0.001 手续费率（0.1%）
fee_currency quote 手续费币种（quote / base）

6.2 手续费计算

· 手续费 = 成交额 × fee_rate
· 成交额 = 成交价 × 成交量
· 手续费从 balance 扣（如果 fee_currency = quote）
· 或从持仓扣（如果 fee_currency = base）

6.3 手续费的记录

· 每笔订单记录手续费
· 手续费累计到账户
· 快照记录累计手续费

6.4 手续费的可配

· 不同用户可配不同费率
· 不同实例可配不同费率
· 支持"模拟 VIP 费率"（用户可手动调低）

七、滑点怎么算

7.1 滑点配置

配置 默认 说明
slippage 0.0 滑点（百分比）
slippage_mode fixed fixed / random

7.2 滑点计算

固定滑点：

· 买单价 = 成交价 × (1 + slippage)
· 卖单价 = 成交价 × (1 - slippage)

随机滑点：

· 在 [0, slippage] 之间随机取值
· 买单加、卖单减
· 更接近真实市场

7.3 滑点的影响

· 滑点直接改变成交价
· 影响盈亏
· 影响手续费（因为手续费基于成交额）

7.4 滑点的记录

· 每笔订单记录实际滑点
· 快照记录累计滑点

八、限价单怎么处理

8.1 两种模式

模式 说明
立即成交模式（默认） 限价单立即检查是否可成交
挂单簿模式（可选） 限价单进挂单簿，价格触及才成交

8.2 立即成交模式

· 买单：limit_price >= ask → 成交；否则 → 拒绝或挂单
· 卖单：limit_price <= bid → 成交；否则 → 拒绝或挂单

默认行为：不成交则挂单（进挂单簿），等待价格触及。

8.3 挂单簿模式

· 限价单进挂单簿
· 每次 tick 检查：
  · 买单：ask <= limit_price → 成交
  · 卖单：bid >= limit_price → 成交
· 用户可随时撤单
· 挂单簿按价格排序

8.4 挂单簿的数据结构

```
挂单簿：
  symbol: BTC/USDT
  buy_orders:
    - { id, price, amount, created_at }
  sell_orders:
    - { id, price, amount, created_at }
```

8.5 挂单簿的撮合

每次 tick：

1. 遍历买单，ask <= limit_price 的成交
2. 遍历卖单，bid >= limit_price 的成交
3. 更新账户
4. 更新挂单簿

8.6 挂单簿的限制

· 每实例挂单数上限（默认 100）
· 挂单簿大小限制
· 挂单超时未成交可自动撤（可配）

九、净值怎么算

9.1 净值的定义

净值 = 账户当前的总价值（USDT 计价）。

```
净值 = balance + Σ(持仓数量 × 当前价格)
```

9.2 净值的组成部分

部分 说明
balance USDT 余额
positions_value 持仓市值
unrealized_pnl 未实现盈亏（已包含在持仓市值里）
realized_pnl 已实现盈亏（已包含在 balance 里）

9.3 净值的计算频率

· 每次 tick 后计算
· 每次成交后计算
· 快照时计算

9.4 高水位净值

· 记录历史最高净值
· 用于计算最大回撤
· 每次净值更新时对比

9.5 最大回撤

```
最大回撤 = (peak_equity - current_equity) / peak_equity
```

9.6 收益率

```
收益率 = (current_equity - initial_balance) / initial_balance
```

9.7 年化收益率

```
年化 = (1 + 收益率) ^ (365 / 运行天数) - 1
```

（可选展示）

十、快照怎么存

10.1 快照的定义

快照 = 某一时刻模拟账户的完整状态记录。 用于历史查询、图表、对比。

10.2 快照的内容

字段 说明
instance_id 所属实例
timestamp 时间
equity 净值
balance 余额
positions 持仓清单
realized_pnl 已实现盈亏
unrealized_pnl 未实现盈亏
peak_equity 高水位
drawdown 当前回撤

10.3 快照的频率

分层采样，避免数据爆炸：

时间范围 采样频率
最近 1 小时 每分钟
最近 24 小时 每 5 分钟
最近 7 天 每小时
最近 30 天 每 6 小时
更早 每天

10.4 快照的存储

· 存 paper_snapshots 表
· 索引：instance_id + timestamp
· 按时间分区（可选）

10.5 快照的清理

· 超过 90 天的原始快照降采样
· 超过 1 年的删除
· 保留策略可配

10.6 快照的查询

· 按实例查
· 按时间范围查
· 返回时间序列数据
· 前端画曲线

十一、多盘怎么对比

11.1 对比的定义

多盘对比 = 把多个模拟盘的净值曲线放在一起，比较它们的表现。

11.2 对比的维度

维度 说明
净值曲线 绝对净值随时间变化
归一化曲线 从 100 起，收益率对比
回撤曲线 回撤随时间变化
收益率 总收益率
最大回撤 最大回撤
夏普比率 风险调整后收益
胜率 盈利订单占比
盈亏比 平均盈利 / 平均亏损
订单数 总订单数
运行时长 运行时间

11.3 对比的筛选

用户可以：

· 选多个实例对比
· 选时间范围
· 选对比指标

11.4 对比的权限

· 用户：只能选自己的实例
· 管理员：可以跨用户对比
· super_admin：可以全站对比

11.5 对比的数据来源

· 从 paper_snapshots 表聚合
· 按统一时间轴对齐
· 时间轴粒度可配（分钟/小时/天）

11.6 对比的性能

· 大量数据的对比要缓存
· 常用对比结果缓存 5 分钟
· 非常用对比实时计算

十二、归一化怎么做

12.1 为什么归一化

不同模拟盘的：

· 初始资金不同（1000 / 5000 / 10000）
· 起跑时间不同（有的跑了 1 天，有的跑了 10 天）

直接比净值不公平，需要归一化。

12.2 归一化的方法

方法 1：按初始资金归一化

```
归一化净值 = 当前净值 / 初始资金 × 100
```

所有实例都从 100 起，看谁涨得多。

方法 2：按时间对齐

· 以最早的实例为起点
· 其他实例在起点之前补 null
· 时间轴统一

方法 3：按收益率归一化

```
收益率 = (当前净值 - 初始净值) / 初始净值
```

直接比收益率。

12.3 归一化的展示

前端提供两种视图切换：

· 绝对净值：显示原始净值
· 归一化：都从 100 起

12.4 归一化的边界

· 初始资金为 0 的实例不参与归一化
· 起跑时间晚的实例前面补 null
· 时间轴对齐到最早实例的起点

十三、模拟盘怎么隔离

13.1 隔离的维度

维度 说明
资金隔离 每个实例独立账户
持仓隔离 每个实例独立持仓
订单隔离 订单带 instance_id
快照隔离 快照带 instance_id
用户隔离 不同用户的模拟盘完全隔离
实例隔离 不同实例完全隔离

13.2 与实盘的隔离

· 模拟盘不调币安 API
· 模拟盘不消耗 API 限频
· 模拟盘不影响真实持仓
· 模拟盘和实盘共享行情
· 模拟盘和实盘共享策略代码
· 模拟盘和实盘共享订单表（但通过 paper 字段区分）

13.3 隔离的实现

· 模拟撮合引擎只处理 paper=true 的实例
· 订单中心根据实例的 paper 字段决定路由
· 连接池不参与模拟盘
· 模拟账户独立存储

13.4 隔离的意义

· 用户可以放心测试策略
· 不影响真实资金
· 可以并行跑多个模拟盘对比

十四、插件在模拟盘怎么生效

14.1 结论

插件挂在作用域上，不挂在实例上。实例是模拟盘还是实盘，不改变绑定的解析结果。

推论：装了插件就自动覆盖模拟盘，不需要为模拟盘单独配置，也不会因为实例是模拟盘就跳过。作用域、生效链与钩子类型见《插件规范》，本节只讲模拟盘下的表现。

14.2 作用的范围

解析规则与实盘一致，但模拟盘实例不绑账号，可挂靠的作用域少一级：

| 作用域 | 对模拟盘实例 |
|---|---|
| `global` | 生效，覆盖全系统 |
| `user` | 生效，覆盖该用户全部实例 |
| `account` | 不生效，模拟盘实例没有账号可挂靠 |

账号级绑定挂的是账号，模拟盘实例的`account_id`为空，这类绑定到不了模拟盘。

这是“模拟盘不绑账号”的直接后果，不是对模拟盘的额外限制。框架不为模拟盘设影子账号，也不提供把账号级绑定映射到模拟盘的配置。

对用户的影响：

- 依赖账号级插件的拦截（如某账号禁止某交易对），在模拟盘上不会发生，模拟盘可能放行实盘会被拒的订单
- 需要模拟盘与实盘拦截一致时，把插件绑在用户级或全局级
- 多盘对比时，前端在模拟盘实例上标注“账号级插件未生效”

14.3 订阅型钩子

模拟盘的事件照常发布到事件总线，订阅型钩子照常收到：

- 订单事件：`order.created`、`order.filled`、`order.partial`、`order.rejected`
- 持仓与保护事件：`position.changed`、`guard.placed`、`guard.triggered`、`guard.missing`
- 告警事件：`system.alert`、`risk.circuit_break`、`instance.auto_stopped`

插件的订阅声明不用改，事件名与实盘共用同一套清单。

14.4 拦截型钩子

四个检查点在模拟盘同样执行，插件的判定同样生效：

- `instance.before_start`：模拟实例启动前同样过拦截链
- `order.before_submit`：模拟下单前同样过拦截链，插件可以否决模拟订单
- `position.before_close`：模拟平仓前同样过拦截链
- `params.before_save`：模拟实例的参数保存前同样过拦截链

插件在模拟盘返回`DENY`时订单同样被拒，顺序仍是风控先于插件，插件在模拟盘同样不能下单。

拦截行为在两边一致是刻意的：模拟盘的验证结果要对实盘有参考价值。

14.5 出网类插件

下单不出网，不代表插件不出网。这是用户需要特别注意的一条。

- 模拟盘的订单走本地撮合，不发币安，不消耗API限频
- 声明了`network`的插件照常真实出网，只能访问`hosts`白名单
- 通知类插件照常推送，模拟盘的成交与告警会被一起发出去
- 报表类插件产出的是模拟数据，接收方需要自行分辨

出网被拒或超时的兜底见《异常与容错》。

十五、模拟盘怎么一致性保证

15.1 一致性的定义

一致性 = 模拟盘的账户状态、订单记录、持仓记录三者相符。

15.2 不一致的场景

场景 说明
进程崩溃 内存状态未落库
数据库写失败 状态部分更新
并发下单 竞态条件
快照失败 快照缺失

15.3 一致性保证机制

机制 1：事务

· 每次成交：更新账户 + 写订单 + 更新持仓在一个事务里
· 事务失败 → 全部回滚

机制 2：实例级锁

· 同一实例的成交串行
· 避免并发竞态

机制 3：定时对账

· 每隔 N 秒对账模拟盘
· 对比账户、订单、持仓
· 不一致 → 修正 + 告警

机制 4：崩溃恢复

· 进程重启后从库恢复账户
· 检查订单和持仓是否相符
· 不一致 → 修正

15.4 对账规则

模拟盘对账：

1. 从订单表重算持仓和余额
2. 与账户表的持仓和余额对比
3. 不一致 → 以订单表为准修正账户表
4. 记录差异

15.5 一致性的边界

· 不保证跨实例一致（不同实例独立）
· 不保证实时一致（有延迟）
· 保证最终一致（通过对账）

十九、模拟盘的重置

19.1 重置的定义

重置 = 把模拟盘恢复到初始状态。

· 清空持仓
· 清空挂单
· 清空订单历史（可选，默认保留）
· 清空快照（可选，默认保留）
· 余额恢复为初始资金
· 记录审计

19.2 重置的条件

· 实例必须是停止状态
· 用户主动点击重置
· 二次确认

19.3 重置后的行为

· 实例状态保持 stopped
· 用户需手动启动
· 启动后从零开始

19.4 重置的限制

· 每小时最多重置 N 次（防滥用）
· 重置不影响其他实例
· 重置不删除订单历史（除非用户选择）

二十、模拟盘的常见问题

20.1 模拟盘和实盘能同时跑同一个策略吗

能。 同一个策略，可以创建两个实例：

· 一个实盘（绑账号）
· 一个模拟盘（不绑账号）

两者共享策略代码，独立运行，独立记录，可以对比。

20.2 模拟盘能用作实盘的预演吗

能。 用户在实盘前先跑模拟盘，验证策略：

· 参数是否合理
· 收益是否符合预期
· 回撤是否可接受

确认后再上实盘。

20.3 模拟盘的行情是真的吗

是真的。 模拟盘用行情中心的实时行情，不延迟、不模拟。

20.4 模拟盘的手续费是真的吗

不是。 模拟盘手续费按配置扣除，和币安实际费率可能不同。用户可以手动配置成币安的实际费率。

20.5 模拟盘能模拟强平和资金费率吗

不能。 BAMY 只做币安现货，现货没有杠杆、强平和资金费率。这两项属于 U 本位合约，随合约扩展位一起预留，不实现。

20.7 模拟盘能跑多久

无限期。 只要实例在运行，模拟盘就持续。

20.8 模拟盘能对比多少个

· 用户：一次最多对比 10 个
· 管理员：一次最多对比 50 个

20.9 模拟盘会触发插件吗

会。 插件按作用域解析，与实例是实盘还是模拟盘无关，订阅型与拦截型钩子在模拟盘照常执行。

只有账号级绑定到不了模拟盘，因为模拟盘实例不绑账号。详见第十四节。

20.10 模拟盘里的插件会真的联网吗

会。 下单不出网，插件出网。声明了`network`的插件在模拟盘照常真实访问白名单主机。

通知类插件会把模拟盘的成交与告警一起推出去，接收方需要自行分辨。
