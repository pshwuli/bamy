> 不写代码，只写规则和逻辑。本文档是完整设计，不是第一版，是最终态。

### 4.7 strategies

字段 类型 约束 说明
id VARCHAR(32) PK 策略 ID，等于目录名
kind VARCHAR(16) NOT NULL 固定为 strategy
name VARCHAR(64) NOT NULL 显示名
version VARCHAR(32) NOT NULL 版本
author VARCHAR(64) NULL 作者
description TEXT NULL 描述
tags TEXT NULL 标签（JSON）
capabilities TEXT NOT NULL 能力（JSON）
params_schema TEXT NOT NULL 参数 schema（JSON）
runtime TEXT NULL 运行配置（JSON）
dependencies TEXT NULL 依赖（JSON）
min_bamy_version VARCHAR(32) NULL 最低 BAMY 版本
loaded BOOLEAN DEFAULT false 是否加载成功
load_error TEXT NULL 加载错误
loaded_at TIMESTAMP NOT NULL 加载时间

索引：

- PRIMARY KEY (id)
- INDEX (loaded)

说明：

- 一行对应一个策略包，即 extensions/strategies/ 下的一个目录。
- kind 恒为 strategy，是判别列，用于与插件包区分；插件包的 kind 恒为 plugin，两者取值互斥。
- 本表不建 kind 索引：该列取值恒定，索引无选择度。
- capabilities、params_schema、dependencies、runtime 均为 JSON。
- 策略一律禁止出网，本表不设出网字段。
- 本表不含实例参数值；实例参数存在 instances.params。

settings_schema TEXT NULL 设置 schema（JSON）
dependencies TEXT NULL 依赖（JSON）

loaded_at TIMESTAMP NOT NULL 加载时间

索引：

- PRIMARY KEY (id)
- INDEX (loaded)
- INDEX (data_scope)

说明：

- 一行对应一个插件包，即 extensions/plugins/ 下的一个目录。
- kind 恒为 plugin，是判别列，用于与策略包区分。
- 本表不建 kind 索引：该列取值恒定，索引无选择度。
- 插件不产生交易意图，本表不含策略的能力声明与参数 schema。
- scopes 至少一个元素，取值 global / user / account；default_scope 必须落在 scopes 内。
- data_scope 为 all 时仅管理员可安装。
- network 为空表示完全禁止出网；声明后才按 hosts 白名单放行。
- 插件本体的加载状态属于插件中心，绑定关系见 4.9。

### 4.9 plugin_bindings

字段 类型 约束 说明
id BIGINT PK, AUTO 主键
plugin_id VARCHAR(32) FK, NOT NULL 插件
plugin_version VARCHAR(32) NOT NULL 绑定时的插件版本
scope VARCHAR(16) NOT NULL global / user / account
scope_id BIGINT NULL 作用域 ID，global 时为 NULL
owner_id BIGINT FK, NOT NULL 绑定创建者，全局绑定为管理员
enabled BOOLEAN DEFAULT true 是否启用
settings TEXT NULL 该绑定的设置值（JSON，secret 类型加密存储）
priority INT DEFAULT 100 拦截链执行顺序，数值小者先执行
status VARCHAR(16) NOT NULL enabled / disabled / invalid
last_error TEXT NULL 最后错误
created_at TIMESTAMP NOT NULL 创建时间
updated_at TIMESTAMP NOT NULL 更新时间
deleted_at TIMESTAMP NULL 软删除时间

索引：

- PRIMARY KEY (id)
- INDEX (plugin_id)
- INDEX (scope, scope_id)
- INDEX (owner_id)
- INDEX (status)

唯一约束：

- UNIQUE (plugin_id, scope, scope_id) WHERE deleted_at IS NULL

说明：

- scope 为 global 时 scope_id 为 NULL；为 user 时存 user_id；为 account 时存 account_id。不设实例级作用域。
- owner_id 不可省略：全局绑定的 owner_id 为管理员 ID，审计记录与权限过滤都依赖该字段。
- 唯一约束按插件的 allow_multiple 放宽。allow_multiple 为 false 时，同一插件在同一作用域上只允许一份绑定。
- allow_multiple 为 true 时，同一作用域允许多份绑定，唯一约束不生效，链路次序由 priority 决定。
- global 作用域下 scope_id 为空值，空值在唯一约束中互不相等，因此全局绑定的唯一性由应用层保证：同一插件至多一份全局绑定。
- 同一插件在 account、user、global 三处可以各有一份绑定，生效时按插件去重，取优先级最高的一份；去重结果不落库，实时计算。
- enabled 是用户的启停意愿，status 是框架的判定结果，两者互不覆盖。
- 插件连续异常超阈值被自动停用时，status 置为 disabled，enabled 保持不变。
- 插件本体卸载时，其全部绑定的 status 置为 invalid。
- settings 的键集由插件包的 settings_schema 决定，同一插件在不同作用域上的 settings 互相独立。
- 除 owner_id 外不再冗余归属字段，账号级绑定按 scope_id 回溯账号，用户级绑定按 scope_id 回溯用户。

### 4.10 plugin_health

字段 类型 约束 说明
id BIGINT PK, AUTO 主键
plugin_id VARCHAR(32) FK, NOT NULL 插件
binding_id BIGINT FK, NULL 绑定，插件级统计时为 NULL
invoke_count BIGINT DEFAULT 0 调用次数
error_count BIGINT DEFAULT 0 异常与超时次数
avg_cost_ms INT NULL 平均耗时
last_error TEXT NULL 最近一次错误原文
last_error_at TIMESTAMP NULL 最近一次错误时间
updated_at TIMESTAMP NOT NULL 更新时间

索引：

- PRIMARY KEY (id)
- INDEX (plugin_id, binding_id)
- INDEX (updated_at)

说明：

- binding_id 为 NULL 的行是该插件的汇总，每个插件至多一行。
- binding_id 非 NULL 的行是单个绑定的统计，每个绑定至多一行。
- 两级各至多一行由写入逻辑保证，不设唯一约束，原因是含 NULL 的唯一约束在各数据库中语义不一致。
- 调用次数按订阅型与拦截型分别计入 invoke_count。
- 本表可重建，丢失不影响正确性，只影响健康度展示。

plugin_bindings.scope_id 是唯一不设数据库级外键的引用字段：它按 scope 指向不同的表，且 global 作用域下为空。

### 5.3 冗余字段

部分表冗余存储 owner_id，目的是：

- 加快用户级查询（不用 join）
- 便于权限过滤
- 减少多表关联

冗余字段必须保持一致：主表更新时，冗余字段跟随更新。

plugin_bindings 的 owner_id 不属于冗余：它记录的是绑定创建者，是这一行的原始归属，不随 scope 变化。
全局绑定的 owner_id 为管理员 ID，用户级与账号级绑定为创建者用户 ID。审计与权限过滤都以该字段为准。

## 八、敏感数据的加密

### 8.1 加密范围

数据 加密方式
用户密码 bcrypt 哈希
API secret AES-256-GCM
API key AES-256-GCM
2FA secret AES-256-GCM
恢复码 AES-256-GCM
API Token SHA-256 哈希
Refresh Token SHA-256 哈希
Session Token SHA-256 哈希
Share Token 随机生成，不加密（本身是随机数）
插件绑定的 settings 中 secret 类型字段 AES-256-GCM，按字段独立加密

插件绑定的 settings 说明：

- settings 整体以 JSON 存储，仅 type 为 secret 的字段加密，其他类型字段明文存储。
- 密文写在 JSON 值的原位上，读取时由框架解密后交给插件，插件与前端都不见到密文。
- 加密后的 secret 字段永不回显，前端只显示"已设置"与替换入口。
- 同一插件在不同绑定上的 secret 各自独立加密，互不影响。

### 8.2 加密密钥管理

- 主密钥从环境变量读
- 每个加密字段用独立 IV
- 密钥不落库、不落日志
- 密钥轮换：支持多版本密钥

### 8.3 加密字段的回显

- API secret：永不回显
- API key：只显示前缀和后缀
- 密码：永不回显
- 2FA secret：永不回显
- 插件绑定的 settings：仅 secret 类型字段永不回显，其余字段原样返回

类型 说明

### 10.4 扩展相关迁移

扩展相关的结构调整按以下规则处理：

- 原 plugins 单表拆为 strategies 与 plugins 两张元信息表，属于结构变更加数据迁移的组合。
- 原表只描述策略包，其全部行迁入 strategies，并按扫描结果补上 kind 字段。
- plugins 表由重新扫描 extensions/plugins/ 填充，不做行迁移。
- 原 instances.plugin_id、plugin_version 改名为 strategy_id、strategy_version，改名不改变取值。
- 新增 plugin_bindings：已启用的插件包按 default_scope 补一份默认绑定，owner_id 取管理员 ID。
- 新增 plugin_health：空表起步，统计在运行中累积。
- 上述变更在同一版本内完成，迁移期间实例不可启动。

### 10.5 迁移的回滚

- 每个迁移有对应的回滚脚本
- 回滚前备份
- 回滚记录审计
