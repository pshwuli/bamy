BAMY 账号模块设计

本文档是 BAMY 框架的第二份设计文档，定义：账号是什么、从哪来、怎么验证、怎么存活、怎么隔离、怎么失效、怎么恢复、怎么删除。
不写代码，只写规则和逻辑。本文档是完整设计，不是第一版，是最终态。

一、文档要回答的问题

1. 账号是什么
2. 账号从哪来
3. 账号怎么验证
4. 账号怎么存活（探活）
5. 多账号怎么隔离
6. 账号失效怎么办
7. 账号怎么恢复
8. 账号怎么删除
9. 账号和实例、订单、行情的关系
10. 账号的安全边界

二、账号是什么

2.1 定义

账号 = 一份币安 API 凭证 + 一组运行状态 + 一个归属用户。

它是 BAMY 与币安之间的接入单位。一个账号对应币安上的一个 API Key。

2.2 账号不是什么

· 账号不是实例。实例是“账号 + 策略 + 参数”的组合，账号只是其中一环。
· 账号不是用户。用户可以有多个账号。
· 账号不是策略，也不是插件。策略经实例运行，插件挂作用域，两者都和账号正交。

2.3 账号在系统中的位置

```
用户
 └── 账号（1:N）
      └── 实例（1:N）
           └── 订单 / 持仓 / 日志
```

一个用户可以有多个账号，一个账号可以有多个实例。

2.4 账号的组成

部分 说明
身份信息 账号名、备注
凭证 API Key、API Secret（加密存储）
归属 owner_id（哪个用户的）
环境 主网 / 测试网
权限 只读 / 可交易
交易类型 现货（U 本位合约为预留扩展位，未实现）
状态 在线 / 离线 / 异常 / 失效 / 已删除
健康数据 最后探活时间、最后验证时间、连续失败次数
附加配置 IP 白名单（可选）、限频配置（可选）

三、账号从哪来

3.1 新增方式

系统支持四种新增方式：

方式 说明
手动添加 用户在后台填写 API Key / Secret
批量导入 通过 CSV / JSON 批量导入
复制已有 复制一个已有账号的配置（不含密钥）
API 创建 通过 API Token 程序化创建

3.2 手动添加的字段

字段 必填 说明
账号名 是 4-32 字符，同一用户下唯一
API Key 是 币安颁发的 key
API Secret 是 币安颁发的 secret
环境 是 主网 / 测试网
交易类型 是 现货（当前唯一取值，U 本位合约预留）
只读 否 默认否；勾选后只能查询，不能下单
备注 否 自由文本
IP 白名单 否 与币安侧的白名单保持一致

3.3 批量导入

· 支持 CSV 和 JSON 两种格式
· 每行一个账号，字段与手动添加一致
· 导入时逐条验证，验证失败的跳过并记录
· 导入结果返回：成功 N 条、失败 M 条、失败原因列表

3.4 复制已有

· 复制一个已有账号的：账号名（自动加后缀）、环境、交易类型、只读标志、备注
· 不复制：API Key、API Secret、状态、健康数据
· 复制后是一个“半成品”账号，用户需要填入新的密钥

3.5 API 创建

· 通过 API Token 创建，字段与手动添加一致
· 权限范围要求 write 或 admin
· 记录审计：来源标为 api

3.6 账号数量的限制

限制 默认值 可配
每用户账号数上限 20 是
系统总账号数上限 1000 是
批量导入单次上限 50 是

超过限制返回明确错误，不静默截断。

四、账号怎么验证

4.1 验证的时机

账号在以下时机必须被验证：

1. 新增时——立即验证，验证不通过直接拒绝创建
2. 编辑时——如果改了密钥、环境、交易类型，重新验证
3. 启动实例时——实例启动前再验证一次
4. 定时探活时——每隔 N 秒自动验证

4.2 验证的内容

一次完整验证包含：

步骤 说明
1. 格式检查 Key/Secret 长度、字符集是否符合币安格式
2. 连通性 能否连上币安 API
3. 凭证有效性 Key/Secret 是否被币安认可
4. 权限检查 是否有读取权限、是否有交易权限
5. 环境匹配 主网 key 是否用在主网环境、测试网 key 是否用在测试网环境
6. 交易类型检查 该 key 是否有现货交易权限
7. IP 白名单检查 若币安侧设置了 IP 白名单，检查当前 IP 是否在白名单内

4.3 验证的结果

结果 含义 处理
通过 全部检查项通过 状态标记为“在线”
部分通过 有权限但不全（如只能读不能交易） 状态“在线”，但标记权限范围
凭证无效 key/secret 错误 拒绝创建 / 状态“失效”
环境不匹配 主网 key 用在测试网 拒绝创建 / 状态“异常”
权限不足 没有交易权限但标记为可交易 拒绝创建 / 状态“异常”
IP 不在白名单 币安拒绝 状态“异常”，提示 IP 问题
网络问题 连不上币安 状态“未知”，重试

4.4 验证频率

时机 频率
新增时 立即
编辑密钥后 立即
定时探活 默认 60 秒，可配
实例启动前 每次启动时
手动触发 用户点击“验证”按钮

4.5 验证失败的重试

· 网络类失败：自动重试 3 次，间隔 2 秒
· 权限类失败：不重试
· 凭证类失败：不重试
· 环境类失败：不重试
· 重试全部失败 → 状态置为对应状态，记录日志

五、账号怎么存活（探活）

5.1 探活的定义

探活 = 定期检查账号是否还能正常使用。 它不是完整的验证，只检查最核心的一项：能不能调通币安 API。

5.2 探活的内容

检查项 说明
API 连通性 能否调通
凭证有效性 key/secret 是否仍被认可
权限是否变化 原来有交易权限，现在还有吗
限频状态 是否被币安限频
IP 是否仍有效 若配置了 IP 白名单

5.3 探活频率

场景 频率
正常状态 60 秒
异常状态 30 秒（失败后加快探活）
连续失败后 120 秒（退避）
用户手动触发 立即

5.4 探活失败的连续计数

每次探活失败 → 计数 +1；探活成功 → 计数清零。

连续失败次数 动作
1-2 记录日志，不改变状态
3 状态置为“异常”
5 使用该账号的实例全部暂停
10 通知管理员，写审计

5.5 探活恢复

· 一旦探活成功，状态从“异常”恢复为“在线”
· 不自动恢复实例——实例需用户手动启动
· 恢复时记录审计

5.6 探活的并发控制

· 所有账号的探活任务由统一的调度器管理
· 不同账号的探活并行执行，但有并发上限（默认 10）
· 同一账号不允许多个探活任务同时跑
· 探活任务超时时间：10 秒

5.7 探活的副作用

探活不能：

· 产生任何交易
· 修改账号的任何配置
· 影响实例的运行状态（除非连续失败达到阈值）

探活只能：

· 读余额或读账户信息（只读操作）
· 更新账号的健康数据
· 触发状态变更和告警

六、多账号怎么隔离

6.1 隔离的维度

多账号隔离涉及五个维度：

维度 说明
数据隔离 每个账号的数据独立存储，互不可见
连接隔离 每个账号独立的 API 连接
限频隔离 每个账号独立的限频额度
状态隔离 一个账号的异常不影响其他账号
密钥隔离 每个账号的密钥独立加密

6.2 数据隔离

· 每个账号的数据（账号信息、实例、订单、持仓、日志）都带 account_id
· 用户端查询强制按 owner_id + account_id 过滤
· 一个账号被删除时，其关联数据按规则处理（见第十一节）

6.3 连接隔离

· 每个账号有独立的 ccxt 客户端实例
· 不共用连接池（避免一个账号的限频影响另一个）
· 连接池按 account_id 索引
· 连接建立后保持长连接，定期检查活跃性

6.4 限频隔离

· 币安的限频是按 API Key 计算的，不是按 IP
· 因此每个账号有独立的限频额度
· BAMY 为每个账号维护独立的限频计数器
· 一个账号触发限频不影响其他账号

6.5 限频的实现

项目 说明
权重感知 每个 API 有不同权重，BAMY 按权重计数
时间窗口 币安是每分钟滚动窗口
安全阈值 不超过 80% 限额，留余量
触发限频 退避等待，不丢弃请求
429 处理 按币安返回的 Retry-After 等待
418 处理 视为严重事件，冷却该账号 5 分钟

6.6 状态隔离

一个账号的以下状态不传播到其他账号：

· 探活失败
· 限频
· 熔断
· 失效

一个账号的以下状态可能传播（可配）：

· 全局熔断（super_admin 触发）
· 系统级网络问题

6.7 密钥隔离

· 每个账号的 API Secret 独立加密
· 加密使用同一个主密钥（环境变量），但每个 secret 用自己的 IV
· 加密算法：AES-256-GCM（带认证）
· 密钥永不落日志、永不回显

6.8 账号之间的“组”

账号组是可选的分组结构，用于把若干账号当作一个整体施加风控。

组的定义：

· 一个组属于一个用户，不跨用户
· 一个账号最多属于一个组，也可以不属于任何组
· 组不改变账号的连接、限频与凭证，账号始终各自独立连接、各自消耗限频额度

组内共享的状态：

· 熔断：任一组内账号触发熔断，全组一并进入熔断
· 冷却期：任一组内账号进入冷却，全组一并进入冷却
· 风控阈值：单笔限额、单日次数、单日金额按全组累计计算

组与账号的关系规则：

· 账号加入组时，先校验该账号不处于熔断与冷却中；处于则拒绝加入
· 账号退出组时，不继承组内已有的熔断与冷却状态
· 账号在组内期间被删除，先从组内移除，再执行删除校验
· 组被删除时，组内账号全部脱离组，账号本身不受影响
· 未建组时，每个账号视为独立计算风控，行为与建组前的账号完全一致

组的字段：

| 字段 | 说明 |
|---|---|
| `account_group_id` | 账号所属组，可空，空表示不分组 |
| 组名 | 同一用户内唯一 |
| 组描述 | 可选 |

组的边界：组只影响风控与熔断的作用范围，不影响数据归属、不影响权限判定、不影响策略行为。判断某个动作能否执行时，先看账号级规则，再叠加组级规则，两者都不允许才放行。

七、账号失效怎么办

7.1 失效的定义

账号“失效”指：账号的凭证已无法使用，且无法通过重试恢复。 常见原因：

原因 说明
Key 被币安删除 用户在币安后台删了 key
Key 被币安禁用 币安检测异常主动禁用
Secret 被改 用户在币安侧重置了 secret
IP 不在白名单 币安拒绝了当前 IP
权限被撤销 用户在币安侧撤销了权限
账户被冻结 币安冻结了该账户

7.2 失效的检测

失效通过两种方式检测：

1. 探活失败——连续失败达到阈值
2. 实时调用失败——实例下单时收到 401 / 403 / 无效 key 类错误

一旦检测到失效 → 立即将账号状态置为“失效”。

7.3 失效的连带动作

动作 说明
状态置为“失效” 不再探活
停用所有相关实例 使用该账号的实盘实例全部暂停
撤销所有会话 无关，不影响
通知用户 后台通知 + 邮件（可配）
写审计 记录失效时间、原因
记录失效快照 最后一次的余额、持仓（只读保存）

7.4 失效账号的展示

失效账号在后台高亮显示：

· 红色状态标记
· 提示“账号已失效，请更新密钥”
· 显示失效原因
· 显示失效时间
· 显示最后一次成功的余额快照

7.5 失效账号的操作限制

失效账号不能：

· 启动新实例
· 作为新实例的绑定账号
· 执行任何交易操作

失效账号可以：

· 查看历史订单
· 查看历史日志
· 查看余额快照（静态）
· 删除
· 更新密钥（更新后重新验证）

7.6 用户更新密钥

用户在后台编辑失效账号：

1. 输入新的 API Key / Secret
2. 系统立即验证
3. 验证通过 → 状态恢复为“在线”
4. 验证失败 → 保持“失效”，提示原因
5. 恢复后不自动启动之前停用的实例，用户手动启动

八、账号怎么恢复

8.1 恢复的场景

场景 触发
网络抖动导致异常 探活恢复
限频导致异常 等待窗口结束后恢复
失效后用户更新密钥 用户手动更新
用户主动恢复 用户点击“恢复”按钮

8.2 恢复的流程

1. 触发恢复（自动或手动）
2. 立即执行一次完整验证
3. 验证通过 → 状态改为“在线”，记录审计
4. 验证失败 → 保持原状态，记录失败原因
5. 恢复后不自动启动实例

8.3 恢复后的对账

账号恢复后，必须与币安对账：

· 拉取该账号的所有持仓
· 拉取该账号的当前挂单
· 与本地记录比对
· 差异以币安为准修正
· 记录对账日志

对账完成前，不允许启动新实例。

8.4 恢复后的实例启动

用户手动启动实例时：

1. 检查账号状态是否在线
2. 检查账号是否需要重新对账（最近一次对账时间）
3. 对账未完成 → 自动触发对账 → 对账完成后启动
4. 对账已完成 → 直接启动

九、账号怎么删除

9.1 删除的前置检查

删除账号前必须检查：

检查项 不通过的处理
是否有实例在用 拒绝删除，提示先停实例
是否有持仓 提示用户先平仓
是否有挂单 提示用户先撤单
是否正在被操作 拒绝删除，稍后重试

9.2 软删除

默认是软删除。

· 状态置为 deleted
· 数据保留
· 关联实例全部停止（但保留实例记录）
· 关联订单、持仓、日志保留
· 分享 token 全部撤销
· 加密的密钥保留（用于审计）

软删除的账号不显示在默认列表，但可以通过“显示已删除”查看。

9.3 硬删除

只有 super_admin 可以硬删除。

硬删除流程：

1. 必须是软删除状态
2. 二次确认（输入账号名）
3. 检查无持仓、无挂单、无实例
4. 级联删除：账号、关联实例、订单、持仓、日志、快照
5. 记录审计
6. 不可恢复

9.4 删除的连带动作

动作 说明
停用所有实例 软删除时执行
清理连接池 删除后立即清理
撤销分享 token 软删除时执行
停止探活任务 删除后停止
记录审计 记录谁、什么时候、删了哪个

9.5 删除的数据保留期

软删除后，数据保留：

· 账号信息：永久
· 关联订单：按订单保留策略
· 关联日志：按日志保留策略
· 加密密钥：保留（审计需要）

硬删除后：全部立即删除，不可恢复。

十、账号和实例、订单、行情的关系

10.1 账号和实例

· 一个账号可以有多个实例
· 一个实例必须绑定一个账号（模拟盘除外，模拟盘不绑账号）
· 删除账号前必须先处理其所有实例

10.2 账号和订单

· 订单通过实例间接归属账号
· 订单记录里冗余存储 account_id，便于查询
· 一个账号的所有订单 = 该账号所有实例的所有订单

10.3 账号和行情

· 行情不依赖账号——行情是公共数据，不需要 API Key 即可获取
· 因此行情订阅和账号完全解耦
· 一个账号失效不影响行情

10.4 账号和用户

· 账号属于某个用户（owner_id）
· 用户删除账号时，账号从用户空间中消失
· 用户被禁用时，其所有账号状态置为“暂停”（保留凭证）

10.5 账号和 WebSocket

· 每个账号有独立的币安 WebSocket 连接（用户数据流）
· 该连接用于接收订单成交通知、仓位变更通知
· 连接断线自动重连
· 每个账号独立签名订阅用户数据流（币安现货已下线 listenKey），互不影响

十一、账号的安全边界

11.1 密钥存储

项目 规则
加密算法 AES-256-GCM
主密钥 环境变量 ENCRYPT_KEY
每个 secret 的 IV 独立生成
存储形式 密文 + IV + 认证标签
解密时机 仅在建立连接时
解密后内存 用后即清（不缓存明文）

11.2 密钥访问

角色 能否看明文
用户本人 否
admin 否
super_admin 否
系统进程 是（仅解密时）
日志 否
数据库备份 否（备份时脱敏）

11.3 密钥回显

· 新增时用户输入一次，系统存储后永不再回显
· 编辑时只能替换，不能查看原值
· 后台列表显示脱敏形式：AKIA****1234（前 4 后 4）

11.4 IP 白名单

· 币安支持 API Key 的 IP 白名单
· BAMY 允许用户为账号配置“预期的 IP 白名单”（用于校验）
· 每次验证时检查当前 IP 是否在白名单内
· 不在白名单 → 账号标记异常

11.5 只读账号

· 用户可以将账号标记为“只读”
· 只读账号可以：
  · 查余额
  · 查持仓
  · 查订单
  · 作为模拟盘的参考行情源
· 只读账号不能：
  · 下单
  · 撤单
  · 绑定实盘实例

11.6 权限最小化

· BAMY 建议用户创建的 API Key 只开启必要的权限
· BAMY 在验证时会报告权限范围，提示用户是否过大
· 不强制，但会警告

11.7 账号操作审计

所有账号相关操作都记审计：

· 创建
· 编辑
· 验证
· 探活（成功/失败）
· 状态变更
· 失效
· 恢复
· 删除
· 密钥更新

十二、账号的健康监控

12.1 健康指标

指标 说明
在线率 最近 24 小时的探活成功比例
平均响应时间 最近 100 次 API 调用的平均耗时
限频次数 最近 1 小时的 429 次数
错误率 最近 1 小时的 API 调用失败率
最后成功调用时间 最近一次成功的时间
最后失败调用时间 最近一次失败的时间

12.2 健康告警

条件 告警级别
在线率 < 95% 警告
在线率 < 80% 严重
连续失败 3 次 警告
连续失败 5 次 严重
限频次数 > 10 警告
错误率 > 10% 警告
错误率 > 30% 严重

12.3 告警通知

· 后台通知中心（必须有）
· 邮件（可配）
· Webhook（可配）
· 管理员可见所有账号的告警，用户只看自己的

12.4 健康数据保留

· 健康指标：保留 30 天
· 探活日志：保留 7 天
· 告警记录：保留 90 天

十三、账号的扩展性

13.1 多交易所扩展

只支持币安，账号模型预留多交易所：

字段 说明
exchange 交易所标识（默认 binance）

将来加 OKX / Bybit 时，只需：

1. 在接入适配层增加新交易所的 driver
2. 账号创建时选择 exchange
3. 其余逻辑（验证、探活、隔离、失效）复用

13.2 多资产扩展

BAMY 只做币安现货。U 本位合约作为扩展位预留，不实现；币本位交割合约与杠杆不在范围内。

预留方式：

· 账号、实例、订单都带 market_type 字段，当前只接受 spot
· 接入适配层按 market_type 选择 driver，当前只有现货 driver
· 将来接 U 本位合约时，一个账号仍只绑定一种交易类型；同一币安账户要同时做现货和合约，创建两个账号（两份 key）

13.3 测试网支持

· 账号有“环境”字段：主网 / 测试网
· 测试网账号的验证、探活、交易走测试网 API
· 测试网和主网账号完全隔离
· 后台可以切换显示“只看主网”“只看测试网”“全部”
