BAMY 引擎设计

本文档是 BAMY 框架的第五份设计文档，定义：引擎是什么、由哪些子引擎组成、每个子引擎的职责、相互如何协作、数据如何流转、异常如何处理、状态如何恢复。
不写代码，只写规则和逻辑。本文档是完整设计，不是第一版，是最终态。

一、文档要回答的问题

1. 引擎是什么
2. 引擎由哪些子引擎组成
3. 每个子引擎的职责和边界
4. 子引擎之间如何协作
5. 数据如何流转
6. 事件如何分发
7. 异常如何处理
8. 状态如何恢复
9. 性能如何保障
10. 如何监控引擎自身

二、引擎是什么

2.1 定义

引擎 = 系统的运行时核心 = 把行情、策略、订单、账户、对账、保护、风控、模拟撮合全部串起来的调度中心。

它是 BAMY 的“心脏”。用户、账号、插件、实例都是静态配置，只有引擎是动态运行的。引擎负责让实例真正跑起来、跑对、跑稳。

2.2 引擎不是什么

· 引擎不是接口层。接口层负责对外通信，引擎负责内部调度。
· 引擎不是数据库。引擎使用数据库，但不定义数据结构。
· 引擎不是插件。引擎给插件提供能力，插件实现业务。

2.3 引擎的位置

```
接口层（HTTP/WebSocket）
    ↓ 调用
服务层（业务编排）
    ↓ 调用
【引擎层】（本文件定义）
    ↓ 调用
接入适配层（币安/其他交易所）
数据层（数据库）
```

引擎是服务层和接入适配层之间的运行时核心。

2.4 引擎的核心原则

引擎只调度，不做决策。
决策在插件里，执行在引擎里，记录在数据层里。

三、引擎的子引擎清单

引擎由 10 个子引擎组成：

序号 子引擎 英文名 职责
1 行情中心 MarketHub 统一拉行情，分发
2 事件总线 EventBus 事件发布订阅
3 策略调度 Runner 实例调度，生命周期
4 订单中心 OrderCenter 下单路径管理
5 保护中心 GuardHub 保护单管理
6 风控中心 RiskEngine 风控和熔断
7 对账引擎 Reconciler 状态收敛
8 模拟撮合 PaperEngine 模拟盘成交
9 连接池 ClientPool 交易所连接管理
10 用户数据流 UserStream WebSocket 接收账户变更

每个子引擎独立、职责单一、互不侵入。它们通过事件总线通信。

四、子引擎详细设计

4.1 行情中心（MarketHub）

职责： 统一拉取和分发行情，一份行情喂所有实例。

核心功能：

功能 说明
订阅管理 维护“哪些 symbol 被哪些实例订阅”
行情拉取 REST 轮询或 WebSocket
行情分发 把 tick 推给所有订阅者
行情缓存 缓存最新 tick，供策略查询
延迟检测 检测行情是否延迟
数据源管理 支持多个数据源（币安主源 + 备用源）

订阅规则：

· 同一 symbol 只订阅一次（无论多少实例）
· 无实例订阅时自动取消
· 订阅是引用计数

分发规则：

· 每个 tick 广播给所有订阅该 symbol 的实例
· 分发用异步队列，不阻塞
· 队列满时丢弃（不阻塞行情源）

延迟检测：

· 记录 tick 的交易所时间戳
· 与本地时间对比
· 延迟 > 阈值（默认 5 秒）→ 触发告警
· 延迟 > 严重阈值（默认 30 秒）→ 暂停相关实例的开仓

数据源切换：

· 主源（币安 WebSocket）
· 备用源（REST 轮询）
· 主源失败 3 次 → 切备用源
· 主源恢复 → 切回主源

行情类型：

类型 频率 用途
ticker 秒级 价格
kline 分钟级 技术指标
orderbook 秒级 盘口
trade 毫秒级 成交明细

缓存策略：

· 最新 ticker 常驻内存
· 最近 N 根 K 线缓存
· 盘口只缓存最新一份

4.2 事件总线（EventBus）

职责： 系统内所有异步事件的发布-订阅。

核心功能：

功能 说明
发布 任何子引擎可发布事件
订阅 任何子引擎可订阅事件
分发 按主题分发给所有订阅者
隔离 单个订阅者失败不影响其他
记录 关键事件可记录

事件类型：

主题 发布者 订阅者
tick 行情中心 策略调度
order.created 订单中心 审计、WebSocket
order.filled 用户数据流 订单中心、审计
order.failed 订单中心 审计、WebSocket
position.changed 用户数据流 审计
guard.triggered 保护中心 风控、审计
risk.breached 风控中心 策略调度、审计
account.invalid 连接池 策略调度、审计
account.recovered 连接池 策略调度、审计
instance.error 策略调度 审计、WebSocket
reconcile.diff 对账引擎 审计
system.alert 任意 审计、WebSocket

分发规则：

· 同步发布、异步分发
· 每个订阅者有独立队列
· 队列满时丢弃并告警

顺序保证：

· 同一主题的事件按发布顺序分发
· 不同主题无顺序保证

持久化：

· 默认不持久化（内存事件）
· 关键事件（如订单、熔断）由专门的记录逻辑写库
· 事件总线本身不写库

4.3 策略调度（Runner）

职责： 实例的调度中心，管理实例的生命周期。

核心功能：

功能 说明
实例注册 启动时注册实例
实例启动 按流程启动
实例停止 按流程停止
实例恢复 崩溃后恢复
tick 分发 把 tick 分给对应策略
异常处理 捕获策略异常
状态管理 维护实例运行状态

启动流程：

```
接收启动请求
  ↓
获取实例级锁
  ↓
【前置检查】
  ↓
【对账】（实盘）
  ↓
【加载插件类】
  ↓
【创建策略上下文】
  ↓
【实例化策略对象】
  ↓
【调 on_start()】
  ↓
【订阅行情】
  ↓
【标记 running】
  ↓
释放实例级锁
```

停止流程：

```
接收停止请求
  ↓
获取实例级锁
  ↓
【取消行情订阅】
  ↓
【调 on_stop()】
  ↓
【按 stop_action 处理】
  ↓
【销毁策略对象】
  ↓
【标记 stopped】
  ↓
释放实例级锁
```

tick 分发：

· 行情中心发布 tick 事件
· 策略调度收到后，找到订阅该 symbol 的所有实例
· 逐个调用策略的 on_tick
· 每个实例的 on_tick 串行
· 不同实例并行

异常处理：

异常 处理
on_tick 抛异常 捕获、记日志、计数 +1
计数达阈值 自动停止实例
on_start 抛异常 启动失败，状态 error
on_stop 抛异常 记日志，视为停止成功
下单失败 交给订单中心

并发控制：

· 实例级锁：同一实例操作串行
· 账号级锁：同一账号下单串行
· 全局锁：崩溃恢复时使用

状态管理：

· 实例状态存内存 + 数据库
· 内存是权威（运行时）
· 数据库是持久化（重启后恢复）

崩溃恢复：

· 启动时扫描需要恢复的实例
· 按并发上限逐个恢复
· 恢复前先对账

4.4 订单中心（OrderCenter）

职责： 管理所有下单的完整路径。

核心功能：

功能 说明
前置校验 本地校验，不碰币安
发送下单 调连接池
处理返回 成功/失败/未知
对账入队 未知订单进对账队列
订单记录 写库
事件发布 发布订单事件

下单路径（四段处理）：

阶段 1：前置校验

检查项 说明
实例状态 running？
账号状态 在线？非只读？
参数精度 amount/price 符合交易对精度？
风控 单笔、单日、白名单
余额 够不够（实盘查币安，模拟盘查本地）
频率 最近下单次数是否超限

任一失败 → 拒绝，写 rejected 订单，发事件，结束。

阶段 2：发送币安

· 调连接池的 create_order
· 超时 10 秒
· 三种结局：
  · 明确成功
  · 明确失败
  · 超时/网络错/状态未知

阶段 3：处理返回

结局 处理
成功 写订单状态 submitted
明确失败 写订单状态 rejected，不重试
未知 写订单状态 unknown，进对账队列

阶段 4：对账（由对账引擎执行）

· 定时捞 unknown 订单
· 查币安
· 收敛状态

订单类型：

类型 说明
market 市价单
limit 限价单
stop_market 止损市价
stop_limit 止损限价
take_profit 止盈
trailing_stop 追踪止损

订单状态：

状态 说明
pending 待发送
submitted 已提交，等成交
partial 部分成交
filled 完全成交
canceled 已撤销
rejected 被拒绝
unknown 状态未知
failed 未成功（币安没收到）

订单 ID 设计：

· 本地 ID：clientOrderId，BAMY 生成，全局唯一
· 交易所 ID：币安返回
· 两者都存

4.5 保护中心（GuardHub）

职责： 开仓保护、保护缺失检测、异常触发动作。

核心功能：

功能 说明
保护单挂载 开仓时挂保护单
保护单跟踪 跟踪保护单状态
缺失检测 定时检查保护单是否还在
异常处理 保护被强平/撤销后的处理
本地保护 保护接口不可用时的兜底

保护单类型：

类型 说明
stop_loss 止损单
take_profit 止盈单
trailing_stop 追踪止损
liquidation_guard 强平保护

保护单的来源：

· 策略自己挂（通过 ctx.place_protection）
· 框架自动挂（如果实例配置了默认保护）

缺失检测：

· 每隔 N 秒（默认 30 秒）
· 对比本地记录的保护单和币安的实际挂单
· 币安有、本地无 → 记录异常
· 本地有、币安无 → 触发告警，标记“失去保护”
· 数量不一致 → 记录差异

保护被强平后的处理：

· 检测到保护单被执行
· 更新本地持仓
· 记录事件
· 通知策略（调 on_order）
· 通知用户（WebSocket）

本地保护（兜底）：

· 保护接口不可用时（如限频）
· 框架在本地记录“应该挂保护”的持仓
· 定时检查价格，达到触发条件时本地触发市价平仓
· 本地保护标记为“弱保护”，在后台有特殊标识

保护单和订单的关系：

· 保护单也是订单
· 走订单中心的完整路径
· 唯一区别：保护单标记 is_guard = true

4.6 风控中心（RiskEngine）

职责： 全局和账号级的风险控制。

核心功能：

功能 说明
前置风控 下单前检查
熔断 触发/解除熔断
回撤控制 监控回撤
冷却期 单币、策略冷却
对账差异 消费对账差异，触发熔断

风控规则（下单前）：

规则 说明
单笔最大金额 每笔订单不超过 N USDT
单日最大次数 每日下单不超过 N 次
单日最大金额 每日下单总金额不超过 N USDT
交易对白名单 只允许白名单内的交易对
交易对黑名单 禁止黑名单内的交易对
总仓位上限 总持仓不超过 N USDT
单币仓位上限 单币持仓不超过 N USDT

熔断级别：

级别 触发者 影响 解除
账号级 系统 该账号所有实例 管理员手动
用户级 系统 该用户所有实例 用户手动
全局级 super_admin 所有实例 super_admin 手动

熔断触发条件：

条件 熔断级别
对账差异超阈值 账号级
连续错误超阈值 账号级
单日亏损超阈值 账号级
最大回撤超阈值 账号级
账号失效 账号级
系统级异常 全局级
管理员手动 任意

熔断行为：

· 熔断后：只允许平仓，不允许开仓
· 熔断后：暂停所有相关实例
· 熔断记录：写入熔断表
· 熔断通知：WebSocket + 邮件 + Webhook

解除流程：

· 账号级：管理员点击解除，二次确认
· 用户级：用户点击解除，二次确认
· 全局级：super_admin 点击解除，二次确认

回撤控制：

类型 说明
最大回撤 相对高水位权益的回撤
单日最大亏损 当日亏损
单币最大亏损 单币亏损

达到阈值 → 触发熔断。

冷却期：

· 单币冷却：某交易对触发风控后，N 分钟内禁止再次开仓
· 策略冷却：某实例触发风控后，N 分钟内禁止开仓

风控的审计：

· 每次触发风控写审计
· 每次解除风控写审计
· 记录触发原因、触发者、时间

4.7 对账引擎（Reconciler）

职责： 解决“状态未知”和“数据不一致”。

核心功能：

功能 说明
未知订单对账 收敛 unknown 状态
持仓对账 与币安比对
余额对账 与币安比对
崩溃恢复对账 重启后先对账
差异记录 记录所有差异

对账类型：

类型 频率 说明
未知订单对账 30 秒 捞 unknown 订单，查币安
持仓对账 60 秒 与币安比对持仓
余额对账 60 秒 与币安比对余额
崩溃恢复对账 启动时 全部对账

未知订单对账流程：

```
捞 unknown 订单
  ↓
【按 clientOrderId 查币安】
  ↓
【币安返回】
  ├─ 成交 → 状态改 filled
  ├─ 未成交 → 状态改 submitted
  ├─ 部分成交 → 状态改 partial
  ├─ 被拒 → 状态改 rejected
  └─ 无此单 → 状态改 failed
  ↓
【写库】
  ↓
【发事件】
```

持仓对账流程：

```
拉币安持仓
  ↓
【与本地持仓对比】
  ↓
【逐项比对】
  ├─ 一致 → 跳过
  ├─ 币安有本地无 → 补本地
  ├─ 本地有币安无 → 标记本地为“已平”
  └─ 数量不一致 → 以币安为准
  ↓
【记录差异】
  ↓
【差异超阈值 → 触发熔断】
```

余额对账流程：

同持仓对账，比对每个币种的余额。

差异处理：

差异类型 处理
轻微差异（< 1%） 记录，以币安为准修正
中等差异（1%-5%） 记录，以币安为准修正，告警
严重差异（> 5%） 记录，触发熔断

对账的审计：

· 每次对账写审计
· 差异项详细记录
· 修正操作详细记录

4.8 模拟撮合（PaperEngine）

职责： 模拟盘的成交、手续费、滑点、净值快照。

核心功能：

功能 说明
模拟账户管理 每个模拟实例一个账户
撮合 按规则成交
手续费 按配置扣除
滑点 按配置调整价格
净值计算 实时计算净值
快照 定时写入快照

模拟账户：

字段 说明
balance USDT 余额
positions 持仓（symbol -> 数量）
avg_price 均价
last_price 最新价
equity 净值 = balance + 持仓市值

撮合规则：

订单类型 成交价
market last / bid / ask（可配）
limit（买单） min(limit, ask)
limit（卖单） max(limit, bid)
stop_market 触发价
stop_limit 触发价后挂限价单

手续费：

· 按 fee_rate 扣除
· 手续费 = 成交额 × fee_rate
· 从 balance 扣

滑点：

· 买单价 = 成交价 × (1 + slippage)
· 卖单价 = 成交价 × (1 - slippage)

限价单挂单簿（可选）：

· 如果开启 limit_fill = true
· 限价单不立即成交
· 价格触及才成交
· 需要维护挂单列表

净值快照：

· 每隔 N 秒（默认 60 秒）写一次
· 记录 equity、balance、positions
· 存入快照表
· 采样策略：
  · 1 小时内：每分钟
  · 1 天内：每 5 分钟
  · 更久：每小时

模拟盘的限制：

限制 说明
单笔最大金额 按配置
单日最大次数 按配置
不允许负余额 余额不足拒绝
不允许超卖 持仓不足拒绝

模拟盘和实盘的隔离：

· 模拟盘不调币安 API
· 模拟盘不消耗 API 限频
· 模拟盘不影响真实持仓
· 模拟盘和实盘共享行情

4.9 连接池（ClientPool）

职责： 管理所有交易所连接。

核心功能：

功能 说明
连接创建 按需创建
连接缓存 复用连接
连接隔离 每账号独立连接
限频管理 每账号独立限频
连接健康 检测连接活性
连接清理 账号删除时清理

连接隔离：

· 每个账号一个 ccxt 客户端实例
· 不共用连接池
· 独立限频额度

限频管理：

· 币安限频按 API Key 计算
· BAMY 为每个账号维护独立计数器
· 权重感知：每个 API 有不同权重
· 时间窗口：每分钟滚动
· 安全阈值：不超过 80% 限额
· 触发限频：退避等待

限频处理：

情况 处理
接近限额 减速
达到限额 等待窗口重置
429 按 Retry-After 等待
418 冷却该账号 5 分钟

连接健康：

· 定期 ping
· 定期探活
· 连接断开 → 自动重连
· 重连失败 → 标记账号异常

连接清理：

· 账号软删除 → 保留连接（可能恢复）
· 账号硬删除 → 清理连接
· 用户禁用 → 保留连接（可能恢复）

4.10 用户数据流（UserStream）

职责： 通过 WebSocket 实时接收币安账户变更。

核心功能：

功能 说明
listenKey 管理 创建、续期、重建
事件接收 订单、持仓、余额变更
事件解析 转换为内部事件
断线重连 自动重连
状态补拉 重连后补齐

listenKey 生命周期：

· 创建：账号启动时创建
· 续期：每 30 分钟续期一次
· 失效：币安返回失效 → 重建
· 销毁：账号删除时销毁

接收的事件：

事件 说明
ORDER_TRADE_UPDATE 订单更新
ACCOUNT_UPDATE 账户更新
MARGIN_CALL 保证金预警
listenKeyExpired listenKey 过期

事件处理：

· ORDER_TRADE_UPDATE → 更新订单状态 → 发事件
· ACCOUNT_UPDATE → 更新持仓/余额 → 发事件
· MARGIN_CALL → 触发保护 → 发事件

断线重连：

· 检测到断线 → 重连
· 重连后 → 重新创建 listenKey
· 重连后 → 补拉订单和持仓（避免丢事件）

与对账引擎的关系：

· UserStream 做实时收敛
· 对账引擎做定时兜底
· 两者互补，不冲突

十一、引擎的扩展性

11.1 多交易所扩展

引擎通过连接池和接入适配层支持多交易所：

· 每个交易所一个 driver
· 账号表有 exchange 字段
· 引擎按账号的 exchange 调用对应 driver
· 其他子引擎不感知交易所差异

11.2 多资产扩展

引擎通过账号的交易类型支持现货、永续、交割：

· 交易类型决定调用哪个 API
· 引擎不感知差异
· 差异在接入适配层

11.3 插件化扩展

引擎本身不插件化（引擎是核心，应稳定）。

引擎的扩展点：

· 事件总线的订阅者（新订阅者可扩展功能）
· 接入适配层（新交易所）
· 数据层（新存储）

11.4 水平扩展

单机引擎按前述容量设计支持 1000+ 实例。超出单机容量时，按分片扩展：

分片维度：

· 按用户分片：同一用户的实例落在同一引擎实例上
· 按账号分片：同一账号下的实例落在同一引擎实例上

选维度时以账号为优先：账号的连接、限频与对账是天然绑定的，按账号分片可避免同一个账号的连接被多个引擎实例并发使用。

分片规则：

| 项 | 规则 |
|---|---|
| 分片键 | 账号 ID，无账号的模拟盘实例按实例 ID |
| 归属稳定性 | 同一分片键在运行期间始终归属同一引擎实例 |
| 实例迁移 | 只在实例处于已停止状态时迁移，迁移前完成对账 |
| 状态共享 | 引擎实例之间只通过数据库共享状态，不直接互相调用 |
| 单账号约束 | 一个账号的连接与用户数据流只能由归属它的引擎实例持有 |
| 并发上限 | 每个引擎实例的实例数不超过单机容量上限，超出则拒绝创建并提示扩容 |

分片带来的约束：

· 风控的全局阈值需要跨引擎实例聚合，聚合口径以数据库为准
· 熔断的全局级判定由一个引擎实例统一裁决，其余引擎实例执行裁决结果
· 实例调度、状态、锁都需按分片键加前缀，避免跨分片争用
· 行情订阅不按分片复制：同一交易对由各引擎实例各自订阅，不引入行情分片

十四、引擎的数据一致性

14.1 一致性级别

· 订单：强一致（写库后才响应）
· 持仓：最终一致（对账收敛）
· 余额：最终一致（对账收敛）
· 行情：弱一致（不要求跨实例一致）
· 状态：最终一致（重启后收敛）

14.2 事务边界

· 单个订单的写库是事务
· 跨订单的操作不是事务（用事件补偿）
· 对账是幂等的

14.3 幂等性

· 下单用 clientOrderId 幂等
· 对账是幂等的
· 探活是幂等的
· 快照是幂等的（同时间只写一条）

14.4 补偿

· 订单失败 → 补偿（对账）
· 持仓差异 → 补偿（以币安为准）
· 状态不一致 → 补偿（重启后修正）
