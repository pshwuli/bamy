## 二、策略是什么

### 2.1 定义

**策略**是交易决策逻辑：观察行情，产出交易意图，交给框架执行。

策略 = 一个文件夹 = 一份 `strategy.yaml` + 一份 `strategy.py`（+ 可选辅助文件）。

它是 BAMY 中唯一能产生交易意图的东西。框架不认识任何具体策略逻辑，只认识"策略"这个结构。交易的所有业务逻辑、所有参数、所有能力，都由策略自己声明和实现。

### 2.2 策略不是什么

- 策略不是实例。策略是模板，实例是模板的一次运行。
- 策略不是账号。账号是交易所接入单位，和策略正交。
- 策略不是用户。策略属于系统，不属于任何用户。
- 策略不是插件。策略产生交易意图，插件增强框架行为，两者并列且互不可见。
- 策略不能直接下单。策略只能通过框架提供的上下文对象表达意图，由框架落地。

### 2.3 策略在系统中的位置

```
extensions/strategies/
  grid_strategy/     ← 策略
  dca_strategy/      ← 策略
  ma_cross/          ← 策略
      │
      ▼
  被实例引用
      │
      ▼
  实例 = 账号 + 策略 + 参数 + 交易对 + 模拟/实盘标志
```

一个策略可以被多个实例引用，每个实例填不同的参数。

### 2.4 策略与插件的关系

策略和插件是**两个并列的东西**，各自解决一类问题：

| | 策略 | 插件 |
|---|---|---|
| 做什么 | 决定要不要交易、交易多少 | 增强框架对交易的处理 |
| 挂在哪 | 实例（实例绑定账号） | 作用域：全局 / 用户 / 账号 |
| 能否下单 | 能，通过框架 API | 不能，框架不提供下单接口 |
| 谁配置 | 用户，在创建实例时填参数 | 管理员或用户，在绑定上填设置 |
| 变更影响 | 只影响该实例 | 影响该作用域下所有账号与实例 |

两者的交界只有一处：**插件可以在框架的检查点上拦截策略产生的交易意图**。策略对此无感知，也不需要知道有没有插件在拦截。

详见《插件规范》。

### 2.5 策略的核心原则

**框架不懂业务，策略定义业务。**

框架代码里不出现"杠杆""网格""止损"这类词。一切由策略 YAML 声明，框架只负责：

- 读 YAML
- 渲染表单
- 校验参数
- 存储参数
- 传给策略
- 调度生命周期
- 执行意图

策略负责：

- 声明有哪些参数
- 声明需要哪些能力
- 实现交易决策逻辑
- 使用框架提供的 API 表达交易意图

## 三、策略的目录结构

### 3.1 标准结构

```
extensions/strategies/
  grid_strategy/
    strategy.yaml       ← 必须，元信息 + 参数 schema + 能力声明
    strategy.py         ← 必须，策略实现
    __init__.py         ← 必须，导出 STRATEGY 类
    requirements.txt    ← 可选，策略依赖的第三方库
    README.md           ← 可选，策略说明
    helpers/            ← 可选，辅助代码
      __init__.py
      utils.py
    static/             ← 可选，前端静态资源（自定义 UI 时用）
      icon.svg
      config_form.html
```

### 3.2 必须文件

| 文件 | 作用 |
|---|---|
| strategy.yaml | 策略的全部声明：元信息、参数 schema、能力 |
| strategy.py | 策略类的实现 |
| __init__.py | 从 strategy.py 导出 STRATEGY 变量 |

### 3.3 可选文件

| 文件 | 作用 |
|---|---|
| requirements.txt | 策略依赖的额外 Python 包 |
| README.md | 说明文档 |
| helpers/ | 辅助代码目录 |
| static/ | 前端静态资源 |

### 3.4 目录命名规则

- 策略文件夹名 = 策略 ID
- 只允许小写字母、数字、下划线
- 长度 3-32 字符
- 全局唯一（与插件 ID 不在同一命名空间，允许同名，但不建议）
- 不允许以 `__` 开头（避免和系统目录冲突）

### 3.5 加载顺序

框架启动时：

1. 扫描 `extensions/strategies/` 下所有子目录
2. 跳过 `__` 开头的目录
3. 对每个目录检查必须文件是否存在
4. 解析 strategy.yaml
5. 导入 strategy.py
6. 校验能力声明和方法实现是否匹配
7. 全部通过 → 标记为"已加载"
8. 任一失败 → 记入失败列表，不影响其他策略

## 四、strategy.yaml 规范

### 4.1 完整字段

```yaml
# ============ 种类 ============
kind: strategy                       # 必须，固定为 strategy

# ============ 元信息 ============
id: grid_strategy                    # 必须，等于文件夹名
name: 网格策略                        # 必须，显示名
version: 1.0.0                       # 必须，语义化版本
author: bamy                         # 可选，作者
description: 经典网格策略，适合震荡行情  # 可选，描述
tags: [grid, spot]          # 可选，标签
min_bamy_version: 1.0.0              # 可选，最低框架版本
homepage: https://...                # 可选，主页
license: MIT                         # 可选，许可证

# ============ 能力声明 ============
capabilities:
  close_position: true               # 支持平单个仓
  close_positions: true              # 支持平多个仓
  close_all: true                    # 支持平全部
  close_partial: true                # 支持部分平仓
  cancel_order: true                 # 支持撤单
  cancel_all: true                   # 支持撤全部
  set_leverage: false                # 合约预留，现货不用
  set_margin_mode: false             # 合约预留，现货不用
  set_position_mode: false           # 合约预留，现货不用
  list_positions: true               # 支持返回持仓清单
  pause: true                        # 支持暂停
  resume: true                       # 支持恢复
  reset: false                       # 不支持重置

# ============ 参数 schema ============
params:
  - key: grid_num
    label: 网格数量
    type: int
    default: 10
    min: 1
    max: 200
    required: true
    help: 分成几档
    group: 基础

  - key: upper_price
    label: 价格上界
    type: float
    default: 100.0
    min: 0
    required: true
    group: 基础

  - key: lower_price
    label: 价格下界
    type: float
    default: 80.0
    min: 0
    required: true
    group: 基础

  - key: order_type
    label: 委托类型
    type: select
    default: limit
    options:
      - { value: limit, label: 限价 }
      - { value: market, label: 市价 }
    group: 高级

  - key: enable_stop_loss
    label: 启用止损
    type: bool
    default: false
    group: 风险

  - key: stop_loss_pct
    label: 止损百分比
    type: float
    default: 5.0
    suffix: "%"
    group: 风险
    depends_on:
      key: enable_stop_loss
      value: true

# ============ 运行配置 ============
runtime:
  tick_interval: 1                   # 行情回调最小间隔（秒）
  symbols: [BTC/USDT, ETH/USDT]      # 支持的交易对（可选，不填表示全部）
  market_type: [spot]                # 支持的交易类型（当前只有 spot）

# ============ 依赖声明 ============
dependencies:
  python: ">=3.11"
  packages:                          # 等价于 requirements.txt
    - pandas>=2.0.0
    - numpy>=1.24.0

# ============ 前端扩展（可选） ============
ui:
  icon: static/icon.svg              # 自定义图标
  custom_form: static/config_form.html  # 自定义参数表单（高级）
```

### 4.2 种类字段

| 字段 | 必填 | 说明 |
|---|---|---|
| kind | 是 | 固定为 `strategy`。框架靠它区分策略包与插件包 |

`kind` 缺失或取值不为 `strategy` 时，该目录不按策略加载。

### 4.3 元信息字段

| 字段 | 必填 | 说明 |
|---|---|---|
| id | 是 | 策略 ID，等于文件夹名 |
| name | 是 | 显示名 |
| version | 是 | 语义化版本 |
| author | 否 | 作者 |
| description | 否 | 描述 |
| tags | 否 | 标签数组 |
| min_bamy_version | 否 | 最低框架版本 |
| homepage | 否 | 主页 |
| license | 否 | 许可证 |

### 4.4 能力声明字段

每个能力对应一个 strategy.py 中的方法。声明了就必须实现，否则该能力不暴露。

| 能力 | 对应方法 | 说明 |
|---|---|---|
| close_position | close_position(id, amount) | 平单个仓 |
| close_positions | close_positions([id, ...]) | 平多个仓 |
| close_all | close_all_positions() | 平全部 |
| close_partial | close_position(id, amount) | 支持部分平（同上，靠 amount 参数） |
| cancel_order | cancel_order(order_id) | 撤单 |
| cancel_all | cancel_all_orders() | 撤全部 |
| set_leverage | set_leverage(n) | 设杠杆 |
| set_margin_mode | set_margin_mode(mode) | 设保证金模式 |
| set_position_mode | set_position_mode(mode) | 设持仓模式 |
| list_positions | list_positions() | 返回持仓清单 |
| pause | pause() | 暂停 |
| resume | resume() | 恢复 |
| reset | reset() | 重置状态 |

`set_leverage`、`set_margin_mode`、`set_position_mode` 是为 U 本位合约预留的能力。BAMY 只做现货，现货实例上框架不调用这三个方法，对应的 `ctx` 方法调用会直接报错；策略在现货下应声明为 false。

### 4.5 参数 schema 字段

每个参数是一个对象：

| 字段 | 必填 | 说明 |
|---|---|---|
| key | 是 | 参数键名，英文，唯一 |
| label | 是 | 显示名 |
| type | 是 | 类型（见第五节） |
| default | 否 | 默认值 |
| required | 否 | 是否必填，默认 false |
| help | 否 | 帮助文本 |
| placeholder | 否 | 占位符 |
| group | 否 | 分组名（前端分组显示） |
| depends_on | 否 | 依赖另一个参数（条件显示） |
| min | 否 | 最小值（int/float） |
| max | 否 | 最大值（int/float） |
| step | 否 | 步进（int/float） |
| suffix | 否 | 后缀（如 %、USDT） |
| pattern | 否 | 正则（string） |
| options | 否 | 选项（select/multiselect） |
| max_length | 否 | 最大长度（string/text） |
| secret | 否 | 是否为敏感字段（前端用密码框） |

## 五、参数类型

### 5.1 支持的类型

| 类型 | 前端渲染 | 后端校验 |
|---|---|---|
| int | 数字框（整数） | 整数、min/max |
| float | 数字框（小数） | 数字、min/max |
| string | 文本框 | 长度、pattern |
| text | 多行文本框 | 长度 |
| bool | 开关 | 布尔 |
| select | 下拉框 | 值在 options 内 |
| multiselect | 多选框 | 值都在 options 内 |
| secret | 密码框 | 长度、存储加密 |
| symbol | 交易对选择器 | 合法的交易对 |
| date | 日期选择器 | 合法日期 |
| time | 时间选择器 | 合法时间 |
| datetime | 日期时间选择器 | 合法日期时间 |
| duration | 时长选择器 | 合法时长（秒/分/时） |
| percent | 百分比输入 | 0-100 |

### 5.2 未知类型处理

- 策略 YAML 里写了框架不认识的 type → 加载时警告，跳过这个参数
- 前端不渲染它
- 该参数不出现在实例配置里
- 不会让整个策略加载失败

### 5.3 参数分组

- 参数通过 group 字段分组
- 前端按组折叠展示
- 未指定 group 的参数归入"其他"
- 组的顺序按参数中首次出现的顺序

### 5.4 条件显示

参数可通过 depends_on 声明依赖：

```yaml
- key: stop_loss_pct
  label: 止损百分比
  type: float
  depends_on:
    key: enable_stop_loss
    value: true
```

含义：只有当 enable_stop_loss 为 true 时，这个参数才显示。

校验时的处理：依赖不满足的参数不参与必填校验，也不传给策略。

### 5.5 参数 schema 的复用

同一套参数类型与字段定义，被插件用作设置声明。规则完全一致，详见《插件规范》。

## 六、strategy.py 规范

### 6.1 必须实现的内容

```python
from bamy.strategy import BaseStrategy, StrategyContext


class GridStrategy(BaseStrategy):
    """策略类，名字随意，但必须继承 BaseStrategy"""

    async def on_start(self):
        """实例启动时调用一次。可用来初始化内部状态。"""

    async def on_tick(self, tick):
        """行情更新时调用。策略的主要逻辑在这里。"""

    async def on_order(self, order):
        """订单状态变化时调用。可选。"""

    async def on_stop(self):
        """实例停止时调用一次。可用来清理。"""


# 必须导出 STRATEGY 变量
STRATEGY = GridStrategy
```

### 6.2 生命周期方法

| 方法 | 何时调用 | 是否必须 |
|---|---|---|
| on_start() | 实例启动后，订阅行情前 | 是 |
| on_tick(tick) | 每次行情更新 | 是 |
| on_order(order) | 订单状态变化 | 否 |
| on_stop() | 实例停止前 | 是 |
| on_pause() | 实例暂停时 | 否 |
| on_resume() | 实例恢复时 | 否 |
| close_position(id, amount) | 用户点"平仓" | 声明能力时必填 |
| close_positions([ids]) | 用户点"平选中" | 声明能力时必填 |
| close_all_positions() | 用户点"一键全平" | 声明能力时必填 |
| cancel_order(order_id) | 用户点"撤单" | 声明能力时必填 |
| cancel_all_orders() | 用户点"撤全部" | 声明能力时必填 |
| set_leverage(n) | 框架或用户调用 | 声明能力时必填 |
| set_margin_mode(mode) | 框架或用户调用 | 声明能力时必填 |
| set_position_mode(mode) | 框架或用户调用 | 声明能力时必填 |
| list_positions() | 用户查看持仓 | 声明能力时必填 |
| pause() | 用户点"暂停" | 声明能力时必填 |
| resume() | 用户点"恢复" | 声明能力时必填 |
| reset() | 用户点"重置" | 声明能力时必填 |

### 6.3 异常处理

- 策略抛出的所有异常由框架捕获
- 每次异常记日志、计数
- 连续异常超过阈值（默认 5 次）→ 自动停止实例
- 异常不向上传播，不影响其他实例

### 6.4 异步要求

- 所有生命周期方法必须是 async 函数
- 策略内部的耗时操作必须 await
- 框架保证同一实例的方法调用是串行的（不会并发调用 on_tick）
- 不同实例之间完全并发，一个实例阻塞不影响其他实例

## 七、框架给策略提供的标准 API

### 7.1 上下文对象 StrategyContext

策略通过 self.ctx 访问框架能力。

### 7.2 只读属性

| 属性 | 说明 |
|---|---|
| ctx.instance_id | 实例 ID |
| ctx.symbol | 交易对 |
| ctx.params | 用户填的参数（字典） |
| ctx.account_id | 绑定的账号 ID（模拟盘为 None） |
| ctx.paper | 是否模拟盘 |
| ctx.market_type | 交易类型（当前恒为 spot） |

### 7.3 下单 API

| 方法 | 说明 |
|---|---|
| await ctx.buy(amount, price=None, type_="market") | 买入/开多 |
| await ctx.sell(amount, price=None, type_="market") | 卖出/开空 |
| await ctx.cancel(order_id) | 撤单 |
| await ctx.cancel_all() | 撤全部 |

### 7.4 持仓 API

| 方法 | 说明 |
|---|---|
| await ctx.list_positions() | 返回持仓清单 |
| await ctx.close_position(id, amount=None) | 平单个仓 |
| await ctx.close_positions([id, ...]) | 平多个仓 |
| await ctx.close_all_positions() | 平全部 |

### 7.5 账户 API

| 方法 | 说明 |
|---|---|
| await ctx.fetch_balance() | 查余额 |
| await ctx.set_leverage(n) | 设杠杆 |
| await ctx.set_margin_mode(mode) | 设保证金模式 |
| await ctx.set_position_mode(mode) | 设持仓模式 |

### 7.6 行情 API

| 方法 | 说明 |
|---|---|
| ctx.get_ticker(symbol) | 拿当前 ticker（从缓存） |
| ctx.get_klines(symbol, timeframe, limit) | 拿 K 线 |
| ctx.get_orderbook(symbol, depth) | 拿盘口 |

### 7.7 日志 API

| 方法 | 说明 |
|---|---|
| ctx.log(message, level="info") | 写日志 |
| ctx.log_info(message) | 等价 info |
| ctx.log_warn(message) | 等价 warn |
| ctx.log_error(message) | 等价 error |

### 7.8 状态存储 API

| 方法 | 说明 |
|---|---|
| await ctx.state.get(key) | 读实例级状态 |
| await ctx.state.set(key, value) | 写实例级状态 |
| await ctx.state.delete(key) | 删状态 |

实例级状态是每个实例独立存储的键值对，进程重启后仍保留，供策略"接着跑"。

### 7.9 保护 API

| 方法 | 说明 |
|---|---|
| await ctx.place_protection(side, amount, stop_price) | 挂保护单 |
| await ctx.cancel_protection(id) | 撤保护单 |
| await ctx.list_protections() | 列出所有保护单 |

### 7.10 策略不可见的接口

框架不向策略暴露以下接口，策略也无法感知其存在：

| 不可见的东西 | 原因 |
|---|---|
| 插件与插件绑定 | 插件是框架层能力，策略不需要也不应该知道 |
| 检查点的拦截结果 | 策略表达意图即可，是否被拦截由框架处理 |
| 其他实例的上下文 | 实例之间完全隔离 |
| 其他用户的数据 | 数据按归属隔离 |

策略在模拟盘与实盘上的代码完全相同，但框架对两者的插件解析不同：模拟盘实例不绑账号，只挂全局级与用户级插件，账号级插件对模拟盘不生效。策略对此无感知；同一策略在模拟盘与实盘上的拦截结果可能因此不同，对比结果时需考虑这一点。详见《模拟盘设计》第十四节与《插件规范》第三节。

### 7.11 禁止事项

策略不能：

- 直接 import ccxt 或其他交易所库
- 直接访问网络
- 直接访问数据库
- 直接访问其他实例的上下文
- 直接读环境变量
- 写本地文件（除策略自己的目录）
- 使用 subprocess / eval / exec

框架通过沙箱机制检测并阻止上述行为。

### 8.1 声明与实现的对应

| 能力 | 必须实现的方法 | 签名 |

| set_position_mode | set_position_mode | `async def set_position_mode(self, mode)` |
| list_positions | list_positions | `async def list_positions(self)` |
| pause | pause | `async def pause(self)` |
| resume | resume | `async def resume(self)` |
| reset | reset | `async def reset(self)` |

### 8.2 校验规则

加载策略时框架校验：

- 声明了 close_position → strategy.py 中必须有 close_position 方法
- 声明了 close_all → 必须有 close_all_positions 方法
- ……以此类推

校验失败：

- 记录策略加载警告
- 该能力不暴露给前端（按钮不显示）
- 其他能力正常
- 整个策略不失败

### 8.3 能力的暴露

声明并通过校验的能力，框架会：

- 在实例详情页显示对应按钮
- 按钮样式由框架统一提供
- 点击后调用策略的对应方法
- 结果回显、记日志、记审计

未声明或校验失败的能力，框架不显示对应按钮。

## 九、持仓清单规范

### 9.1 list_positions 的返回格式

list_positions() 返回一个列表，每一项是一个持仓对象：

```python
[
    {
        "id": "pos_001",              # 持仓唯一 ID（策略自己编）
        "symbol": "BTC/USDT",         # 交易对
        "side": "long",               # long / short / none
        "amount": 0.01,               # 数量
        "entry_price": 50000.0,       # 开仓均价
        "mark_price": 51000.0,        # 当前标记价
        "unrealized_pnl": 10.0,       # 未实现盈亏
        "unrealized_pnl_pct": 2.0,    # 未实现盈亏百分比
        "leverage": 3,                # 杠杆
        "label": "第1仓",             # 显示标签
        "opened_at": 1690000000000,   # 开仓时间（毫秒时间戳）
    },
    {
        "id": "pos_002",
        "symbol": "BTC/USDT",
        "side": "long",
        "amount": 0.02,
        "entry_price": 49000.0,
        "label": "第2仓",
        ...
    }
]
```

### 9.2 必须字段

| 字段 | 必填 | 说明 |
|---|---|---|
| id | 是 | 持仓唯一 ID，策略自己维护 |
| symbol | 是 | 交易对 |
| side | 是 | long / short / none |
| amount | 是 | 数量 |
| entry_price | 否 | 开仓均价 |
| mark_price | 否 | 当前标记价 |
| unrealized_pnl | 否 | 未实现盈亏 |
| leverage | 否 | 杠杆 |
| label | 否 | 显示标签 |
| opened_at | 否 | 开仓时间 |

### 9.3 ID 的稳定性

持仓 ID 必须在持仓生命周期内稳定：

- 开仓时生成
- 平仓前不变
- 平仓后失效
- 部分平仓时 ID 不变（amount 变小）

框架依赖这个 ID 来定位要平的仓。

### 9.4 策略自持持仓

策略可以完全不使用"仓"的概念（如网格策略只有分散的挂单）。此时不声明 list_positions 能力即可，框架不显示持仓区。

## 十、策略生命周期

### 10.1 加载

```
启动 → 扫描目录 → 读 strategy.yaml → 导入 strategy.py
     → 校验能力 → 注册策略 → 完成
```

### 10.2 实例化

每个实例启动时：

```
框架 → 加载策略类 → 创建实例 → 注入 ctx → 调 on_start()
```

**每次实例启动，都是一个独立的策略对象。** 不同实例之间不共享策略对象。

### 10.3 运行

```
行情 → 框架 → on_tick(tick) → 策略内部逻辑
                            → 调 ctx.buy/sell
                            → 框架接管下单流程
                            → （沿途可被插件拦截）
```

### 10.4 停止

```
用户点停止 → 框架 → on_stop() → 取消行情订阅 → 状态更新
```

### 10.5 异常

```
策略抛异常 → 框架捕获 → 记日志 → 计数 +1
                          → 连续超阈值 → 自动停实例
```

### 10.6 卸载

```
框架关闭 / 管理员卸载策略 → 停止所有相关实例
                        → 卸载模块
                        → 清理缓存
```

### 10.7 热更新

支持热更新。

流程：

1. 管理员点击"重新扫描扩展"
2. 框架重新扫描 `extensions/strategies/` 目录
3. 对已存在的策略：
   - 如果文件有变化 → 重新加载
   - 如果文件无变化 → 跳过
4. 对新策略：
   - 加载并注册
5. 对消失的策略：
   - 停止所有相关实例
   - 从已加载列表移除
6. 正在运行的实例：
   - 保持原策略代码运行
   - 不中断
   - 下次启动时用新代码
7. 加载失败：
   - 保留旧版本
   - 记录失败原因
   - 管理员可见

### 10.8 热更新的限制

- 不能热更新正在运行的实例的代码（模块重载有风险）
- 只保证"下次启动用新代码"
- 若策略有 requirements.txt 新增依赖，需要重启服务

## 十一、策略安全边界

### 11.1 沙箱目标

策略的代码不能：

- 访问文件系统（除策略自己的目录）
- 发起网络请求（除框架提供的 API）
- 访问数据库
- 访问环境变量
- 访问其他实例的上下文
- 使用 subprocess / eval / exec / compile
- 修改框架内部状态

### 11.2 沙箱实现思路

- 策略只能 import 白名单内的模块（标准库 + 框架提供的 + requirements 里声明的）
- 网络请求必须走 ctx 提供的 API
- 数据库访问必须走 ctx.state 或 ctx 的其他 API
- 通过 AST 静态检查 + 运行时拦截双重防护

### 11.3 白名单模块

策略可以 import：

- 标准库（不含 os、sys、subprocess、socket 等危险模块）
- numpy、pandas、ta 等量化常用库
- bamy.strategy（框架提供的基类和上下文）
- 策略自己 helpers/ 下的模块
- requirements.txt 里声明的第三方库

### 11.4 危险操作拦截

| 操作 | 处理 |
|---|---|
| import os | 拒绝加载 |
| import subprocess | 拒绝加载 |
| import socket | 拒绝加载 |
| open(...) 写文件 | 运行时拦截 |
| eval(...) | 拒绝加载 |
| exec(...) | 拒绝加载 |
| 直接访问 ctx._internal | 运行时拦截 |

### 11.5 沙箱的定位

沙箱只防误操作，不防恶意代码：

- 防止策略作者无意中破坏框架、越过上下文直接访问资源
- 策略与框架运行在同一进程内，不做子进程或容器隔离
- 只安装可信来源的策略包；安装即视为管理员对代码负责
- AST 静态检查与运行时拦截可被刻意绕过，不能作为对抗恶意代码的安全边界

### 11.6 沙箱与插件的差异

插件与策略共用同一套沙箱机制，但两者可达的数据范围不同：

| | 策略 | 插件 |
|---|---|---|
| 数据可见范围 | 本实例 | 由 data_scope 声明（本作用域内 / 全系统） |
| 网络访问 | 一律禁止 | 声明 network 后可访问白名单主机，未声明则禁止 |
| 状态存储 | `ctx.state`，实例级 | `ctx.state`，绑定级 |
| 变更影响面 | 单个实例 | 整个作用域 |

详见《插件规范》第十一节。

## 十二、策略调试与发布

### 12.1 调试模式

策略可以在本地以调试模式运行：

- 框架提供 CLI 工具
- `bamy strategy test <strategy_id>` → 加载策略，跑一遍校验
- `bamy strategy dryrun <strategy_id> --symbol BTC/USDT` → 用模拟数据跑 on_tick
- `bamy strategy form <strategy_id>` → 打印参数表单结构

### 12.2 日志

- 策略通过 ctx.log() 打日志
- 日志自动带实例 ID、策略 ID、时间戳
- 日志分等级：debug / info / warn / error
- 日志写到框架的统一日志系统

### 12.3 发布

- 策略以文件夹形式发布
- 发布方式：
  - 直接拷贝文件夹到 `extensions/strategies/`
  - 通过后台的上传接口上传 zip
  - 从 Git 仓库拉取（可选）

### 12.4 版本管理

- 每个策略有 version 字段

### 13.2 strategy.py

```python
from bamy.strategy import BaseStrategy


class GridStrategy(BaseStrategy):

    def __init__(self, ctx):
        super().__init__(ctx)
        self.grids = []
        self.positions = {}

    async def on_start(self):
        p = self.ctx.params
        n = p["grid_num"]
        up = p["upper_price"]
        lo = p["lower_price"]
        step = (up - lo) / n
        self.grids = [lo + step * i for i in range(n + 1)]
        self.ctx.log(f"网格初始化完成，共 {len(self.grids)} 档")

    async def on_tick(self, tick):
        price = tick["last"]
        # 策略逻辑：价格触及网格时下单
        # 这里只是示例，具体逻辑由策略作者实现
        pass

    async def on_stop(self):
        self.ctx.log("网格策略停止")

    async def list_positions(self):
        # 返回当前持仓清单
        return list(self.positions.values())

    async def close_position(self, position_id, amount=None):
        # 平单个仓
        pos = self.positions.get(position_id)
        if not pos:
            return {"ok": False, "reason": "position not found"}
        # 具体平仓逻辑
        await self.ctx.sell(amount or pos["amount"])
        return {"ok": True}

    async def close_all_positions(self):
        # 平全部
        for pid in list(self.positions.keys()):
            await self.close_position(pid)
        return {"ok": True}


STRATEGY = GridStrategy
```

## 十四、策略失败处理

### 14.1 加载失败

| 原因 | 处理 |
|---|---|
| strategy.yaml 缺失 | 记录失败，跳过 |
| strategy.yaml 格式错 | 记录失败，跳过 |
| strategy.py 缺失 | 记录失败，跳过 |
| strategy.py 语法错 | 记录失败，跳过 |
| STRATEGY 变量缺失 | 记录失败，跳过 |
| STRATEGY 不是类 | 记录失败，跳过 |
| STRATEGY 未继承 BaseStrategy | 记录失败，跳过 |
| kind 不是 strategy | 记录失败，跳过 |
| 能力声明缺对应方法 | 记录警告，能力不暴露 |
| 未知参数类型 | 记录警告，参数跳过 |

任何失败都不影响其他策略加载。

### 14.2 运行时失败

| 情况 | 处理 |
|---|---|
| on_tick 抛异常 | 记日志、计数、超阈值自动停实例 |
| on_start 抛异常 | 实例启动失败，状态置 error |
| on_stop 抛异常 | 记日志，仍视为停止成功 |
| 下单失败 | 走订单中心的分段处理 |
| 平仓失败 | 返回失败原因，不重试（由用户决定） |
| 下单被插件拒绝 | 返回拒绝原因，记审计，计入策略可见的失败 |

### 14.3 失败通知

- 加载失败：管理员后台可见
- 运行时失败：用户后台可见（自己的实例）
- 频繁失败：触发告警

### 14.4 失败恢复

- 加载失败：修复策略文件后，手动触发重新扫描
- 运行时失败：修复后，手动重启实例

## 十五、策略与框架的契约

### 15.1 框架承诺给策略

- 稳定的 BaseStrategy 基类
- 稳定的 StrategyContext 接口
- 稳定的生命周期回调
- 稳定的标准 API
- 稳定的参数传入方式
- 稳定的日志接口
- 稳定的状态存储接口

### 15.2 策略承诺给框架

- 实现必须的生命周期方法
- 实现声明了的能力对应的方法
- 不访问框架禁止的资源
- 参数只从 ctx.params 读
- 下单只通过 ctx 的 API
- 日志只用 ctx.log
- 不直接 import 危险模块

### 15.3 契约与插件的关系

插件可以在策略无感知的情况下拦截策略的下单。这是框架的既定行为，不是契约破坏。策略作者不应假定"调了 ctx.buy 就一定下到交易所"。

### 15.4 契约变更

- 框架升级若改变契约，必须：
  - 提升主版本号
  - 提供迁移指南
  - 策略通过 min_bamy_version 声明兼容性
  - 不兼容的旧策略明确拒绝加载并提示
