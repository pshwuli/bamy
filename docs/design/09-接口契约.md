## 二、接口的整体规范

### 2.1 接口分类

| 类别 | 前缀 | 鉴权 | 数据范围 |
|---|---|---|---|
| 认证 | `/api/auth/*` | 无 | 注册、登录、找回密码 |
| 初始化 | `/api/setup` | 无（首次） | 创建第一个管理员 |
| 用户 | `/api/*` | JWT | 强制按owner_id过滤 |
| 管理员 | `/api/admin/*` | JWT + 角色≥admin | 全局 |
| 超级管理员 | `/api/super/*` | JWT + super_admin | 全局 + 系统级 |
| 访客 | `/view/{token}` | 分享token | 只读，只限该token绑定的实例 |
| 系统 | `/health`、`/metrics` | 无 | 健康检查、监控 |
| WebSocket | `/ws/*` | JWT或分享token | 实时推送 |

### 2.2 命名规范

- 路径用小写 + 中划线（如 /api/strategy-instances）
- 或小写 + 复数（如 /api/instances），统一用复数
- 动作用子路径（如 /api/instances/{id}/start）
- 不用动词做路径（除特殊动作）

### 2.3 HTTP方法

| 方法 | 用途 |
|---|---|
| GET | 查询 |
| POST | 创建、执行动作 |
| PUT | 全量更新 |
| PATCH | 部分更新 |
| DELETE | 删除 |

### 2.4 请求格式

- Content-Type：application/json
- 认证：Authorization: Bearer <token>
- 请求ID：X-Request-Id（可选，用于追踪）
- 时间戳：ISO 8601格式

### 2.5 响应格式

成功响应：

```json
{
  "code": 0,
  "message": "success",
  "data": { ... },
  "request_id": "xxx",
  "timestamp": 1690000000000
}
```

错误响应：

```json
{
  "code": 40001,
  "message": "参数错误",
  "errors": [
    {"field": "amount", "reason": "必须大于0"}
  ],
  "request_id": "xxx",
  "timestamp": 1690000000000
}
```

#### 2.7.1 插件拦截错误码

插件在检查点上拦截时产生三个命名错误码，只出现在拦截型钩子上。订阅型钩子出错不影响调用方，不返回错误码。

| 错误码 | 英文名 | 触发场景 | 前端处理建议 |
|---|---|---|---|
| 42290 | `PLUGIN_DENIED` | 插件按自身规则返回DENY，如禁止该交易对、锁定仓位禁止平仓、参数不合规 | 提示被哪个插件拒绝并原样展示reason；引导用户改绑定设置或联系管理员，不提示重试 |
| 42291 | `PLUGIN_TIMEOUT` | 插件处理超过timeout_ms，且该钩子fail_mode为closed | 提示插件响应超时、操作已被拒绝，附插件名；说明不是系统故障，提供查看绑定健康度的入口 |
| 42292 | `PLUGIN_ERROR` | 插件处理抛异常或返回非法结论，且该钩子fail_mode为closed | 提示插件执行出错、操作已被拒绝，附插件名与错误摘要；管理员端提供查看健康度与停用绑定的入口 |

fail_mode为open时，插件超时与异常不产生错误码，按放行处理，只记日志与告警。

三者的响应`data`中带定位字段，前端据此提示被哪个插件拒绝：

```json
{
  "code": 42290,
  "message": "被插件拒绝",
  "data": {"plugin_id": "risk_guard", "plugin_name": "风控增强", "binding_id": 3, "effective_scope": "global", "checkpoint": "order.before_submit", "reason": "禁止该交易对"},
  "request_id": "xxx",
  "timestamp": 1690000000000
}
```

| 字段 | 说明 |
|---|---|
| plugin_id / plugin_name | 拒绝发生的插件 |
| binding_id | 生效的绑定 |
| effective_scope | 实际生效的作用域：global / user / account |
| checkpoint | 发生拦截的检查点 |
| reason | 插件给出的拒绝原因，`PLUGIN_DENIED`时必有 |

effective_scope为global时，用户无法自行调整该绑定，前端提示联系管理员。

### 2.8 分页规范

请求参数：

| 参数 | 说明 | 默认 |
|---|---|---|
| page | 页码（从1开始） | 1 |
| page_size | 每页数量 | 20 |
| cursor | 游标（用于大数据集） | - |
| sort | 排序字段 | created_at |
| order | 排序方向（asc/desc） | desc |

响应格式：

```json
{
  "code": 0,
  "data": {
    "items": [ ... ],
    "pagination": {
      "page": 1,
      "page_size": 20,
      "total": 1000,
      "total_pages": 50,
      "has_next": true,
      "has_prev": false,
      "next_cursor": "xxx"
    }
  }
}
```

### 2.9 接口版本

版本通过URL路径体现，路径中不带版本号时视为当前版本：

| 形态 | 说明 |
|---|---|
| `/api/instances` | 当前版本，等价于最新版本 |
| `/api/v1/instances` | 显式指定第一版 |
| `Accept: application/vnd.bamy.v1+json` | 通过请求头指定版本 |

规则：

- 同一接口同时支持路径与请求头两种指定方式，两者冲突时以路径为准
- 向后兼容的变更不升版本号：新增字段、新增接口、放宽取值范围
- 破坏性变更升版本号：删除字段、改变字段语义、改变必填性、改变状态机
- 旧版本保留至其调用方全部迁移完成，保留期内新旧版本并存
- 响应头返回当前生效的版本，便于调用方确认
- 已废弃版本在响应中带废弃提示，并在文档中标注

### 2.10 幂等性

- GET、PUT、DELETE天然幂等
- POST通过client_order_id或请求ID实现幂等
- 支持幂等的接口需在契约中注明

## 六、策略、插件与插件绑定接口

本节接口分三组：策略接口供用户选策略建实例；插件市场接口供用户挑选插件；插件绑定接口供用户把插件挂到自己的用户或账号作用域。策略与插件的定义见《策略规范》与《插件规范》。

### 6.1 策略列表

GET /api/strategies

只列出策略包（`kind: strategy`），不含插件包。

响应：

```json
{
  "code": 0,
  "data": {
    "items": [
      {
        "id": "grid_strategy",
        "name": "网格策略",
        "version": "1.0.0",
        "author": "bamy",
        "description": "经典网格",
        "tags": ["grid"],
        "capabilities": {"close_position": true, "close_all": true, ...},
        "loaded": true
      }
    ]
  }
}
```

### 6.2 策略详情

GET /api/strategies/{id}

在列表字段之外，返回创建实例所需的完整声明：

| 字段 | 说明 |
|---|---|
| params_schema | 完整的参数schema，前端据此渲染参数表单 |
| runtime | 运行配置：tick_interval、支持的交易对、支持的交易类型 |
| dependencies | 依赖声明 |

```json
{
  "code": 0,
  "data": {
    "id": "grid_strategy",
    "name": "网格策略",
    "version": "1.0.0",
    "capabilities": {...},
    "params_schema": [
      {"key": "grid_num", "label": "网格数量", "type": "int", "default": 10, "min": 1, "max": 200, "required": true, "group": "基础"}
    ],
    "runtime": {"tick_interval": 1, "symbols": ["BTC/USDT", "ETH/USDT"], "market_type": ["spot"]},
    "dependencies": {"python": ">=3.11", "packages": ["pandas>=2.0.0"]},
    "loaded": true
  }
}
```

策略不存在或未加载时返回40402。

### 6.3 插件市场列表

GET /api/plugins

只列出插件包（`kind: plugin`），不含策略包。查询参数：tags、scope（只看支持该作用域的插件）。

响应：

```json
{
  "code": 0,
  "data": {
    "items": [
      {
        "id": "telegram_notify",
        "name": "Telegram 通知",
        "version": "1.0.0",
        "description": "把系统事件推送到 Telegram",
        "tags": ["notify"],
        "scopes": ["global", "user", "account"],
        "default_scope": "account",
        "data_scope": "own",
        "priority": 100,
        "loaded": true,
        "installable": true,
        "network_hosts": ["api.telegram.org"]
      }
    ]
  }
}
```

| 字段 | 说明 |
|---|---|
| scopes | 插件声明支持的作用域；未声明的作用域，前端不显示对应安装入口 |
| default_scope | 安装时默认选定的作用域 |
| data_scope | `own`或`all`；`all`的插件在市场里显著标注 |
| priority | 拦截链中的默认顺序，新建绑定时作为默认值 |
| installable | 当前用户能否安装；`data_scope`为`all`时对普通用户为false，对管理员为true |
| network_hosts | 出网白名单，供用户在安装前审阅；插件未声明出网时为空数组 |

### 6.4 插件详情

GET /api/plugins/{id}

在列表字段之外，返回安装所需的完整声明：

| 字段 | 说明 |
|---|---|
| settings_schema | 完整的设置schema，类型系统与策略参数相同，前端据此渲染设置表单 |
| hooks | 钩子清单，说明插件订阅哪些事件、在哪些检查点拦截 |
| network | 出网声明：是否出网、主机白名单、超时 |

```json
{
  "code": 0,
  "data": {
    "id": "telegram_notify",
    "name": "Telegram 通知",
    "version": "1.0.0",
    "scopes": ["global", "user", "account"],
    "data_scope": "own",
    "installable": true,
    "settings_schema": [
      {"key": "bot_token", "label": "Bot Token", "type": "secret", "required": true, "group": "凭据"},
      {"key": "min_level", "label": "最低等级", "type": "select", "default": "warn", "group": "规则"}
    ],
    "hooks": [
      {"type": "event", "event": "system.alert"},
      {"type": "event", "event": "order.filled"},
      {"type": "checkpoint", "checkpoint": "order.before_submit", "fail_mode": "open", "timeout_ms": 200}
    ],
    "network": {"enabled": true, "hosts": ["api.telegram.org"], "timeout_ms": 5000}
  }
}
```

hooks中每一项的`type`为`event`（订阅型，只接收事件）或`checkpoint`（拦截型，可否决或改写）。拦截型同时给出`fail_mode`与`timeout_ms`，供用户判断插件异常时的影响。

插件不存在或未加载时返回40406。

查询参数：page、page_size、scope（user/account）、scope_id、plugin_id、status。

响应：

```json
{
  "code": 0,
  "data": {
    "items": [
      {
        "id": 12,
        "plugin_id": "telegram_notify",
        "plugin_version": "1.0.0",
        "scope": "account",
        "scope_id": 1,
        "enabled": true,
        "status": "enabled",
        "priority": 100,
        "settings": {"bot_token": "******", "chat_id": "10001", "min_level": "warn"},
        "created_at": "2024-01-01T00:00:00Z",
        "updated_at": "2024-01-01T00:00:00Z"

```

`secret`类型的设置值一律脱敏返回，不回显明文。`status`取值为`enabled`、`disabled`、`invalid`，含义见《术语表》。

### 6.6 新建插件绑定

POST /api/plugin-bindings

请求：

```json
{
  "plugin_id": "telegram_notify",
  "scope": "account",
  "scope_id": 1,
  "settings": {"bot_token": "xxx", "chat_id": "10001", "min_level": "warn"},
  "priority": 100,
  "enabled": true
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| plugin_id | 是 | 插件ID |
| scope | 是 | `user`或`account`；用户端不接受`global` |
| scope_id | 是 | scope为user时填自己的用户ID；scope为account时填自己的账号ID |
| settings | 否 | 按插件settings_schema校验；无设置的插件可省略 |
| priority | 否 | 默认取插件声明的priority |
| enabled | 否 | 默认true |

响应（201）：

```json
{
  "code": 0,
  "data": {
    "id": 12,
    "plugin_id": "telegram_notify",
    "plugin_version": "1.0.0",
    "scope": "account",
    "scope_id": 1,
    "status": "enabled"
  }
}
```

校验规则，按顺序执行，任一不通过即拒绝：

| 序号 | 规则 | 不通过时的错误码 |
|---|---|---|
| 1 | 插件存在且已加载 | 40406 |
| 2 | scope不为global；普通用户不能创建全局绑定 | 42281 |
| 3 | scope取值合法，scope_id与scope配套 | 42280 |
| 4 | scope在插件声明的scopes内 | 42229 |
| 5 | 插件的data_scope不为all；普通用户不能安装全系统数据范围的插件 | 42282 |
| 6 | scope为user时，scope_id必须是当前用户ID | 40303（以404呈现） |
| 7 | scope为account时，scope_id必须是当前用户名下的账号 | 40303（以404呈现） |
| 8 | 插件allow_multiple为false时，同一作用域上不存在该插件的绑定 | 40913 |
| 9 | settings符合插件settings_schema，必填项齐全 | 42227 / 42228 |

创建成功后立即生效，框架调用插件的on_bind()，并写审计。

### 6.7 修改插件绑定

PATCH /api/plugin-bindings/{id}

请求（字段均可选，只改出现的字段）：

```json
{
  "settings": {"min_level": "error"},
  "priority": 50,
  "enabled": false
}
```

规则：

- 只能修改自己作用域内的绑定，否则返回40303（以404呈现）
- plugin_id、scope、scope_id不可修改；要换作用域，删除后重建
- settings按插件settings_schema校验；`secret`字段不传则保留原值
- 修改settings后立即生效，框架调用on_settings()
- enabled改为false时立即停用，框架调用on_unbind()，配置保留
- 绑定处于`invalid`时不可启用，返回42283
- 绑定因连续异常被自动停用时，用户不能自行启用，返回40914，由管理员恢复

### 6.8 删除插件绑定

DELETE /api/plugin-bindings/{id}

只能删除自己作用域内的绑定。删除立即生效，框架调用on_unbind()，写审计。响应204。

### 6.9 插件绑定健康度

GET /api/plugin-bindings/{id}/health

返回该绑定的运行统计，只能查看自己作用域内的绑定。

响应：

```json
{
  "code": 0,
  "data": {
    "binding_id": 12,
    "plugin_id": "telegram_notify",
    "status": "enabled",
    "auto_disabled": false,
    "event_calls": 1200,
    "checkpoint_calls": 300,
    "error_count": 3,
    "timeout_count": 1,
    "consecutive_errors": 0,
    "avg_latency_ms": 35,

    "since": "2024-01-01T00:00:00Z"
  }
}
```

| 字段 | 说明 |
|---|---|
| event_calls / checkpoint_calls | 订阅型与拦截型钩子的调用次数，分别统计 |
| error_count | 异常次数，抛错与超时之和 |

| avg_latency_ms | 拦截型钩子的平均耗时 |
| last_error | 最近一次错误的原文与时间 |
| auto_disabled | 是否因连续异常被自动停用 |

### 6.12 新建全局插件绑定（管理员）

POST /api/admin/plugin-bindings

请求：

```json

  "plugin_id": "risk_guard",

  "enabled": true
}
```

## 十七、限流规则

| 接口 | 限制 |
|---|---|
| `/api/auth/login` | 每IP每分钟10次 |
| `/api/auth/register` | 每IP每小时5次 |
| `/api/auth/forgot-password` | 每邮箱每小时3次 |
| `/api/*` | 每用户每分钟120次 |
| `/api/admin/*` | 每管理员每分钟300次 |
| `/api/super/*` | 每super_admin每分钟300次 |
| `/view/{token}` | 每token每分钟60次 |
| WebSocket | 每连接每分钟100条消息 |

超限返回429和Retry-After头。

## 十九、接口的版本兼容

### 19.1 兼容性承诺

- 新增字段：兼容
- 新增接口：兼容
- 修改字段类型：不兼容（升版本）
- 删除字段：不兼容（升版本）
- 修改接口语义：不兼容（升版本）

### 19.2 废弃策略

- 标记废弃的接口保留6个月
- 6个月后移除
- 废弃期间返回Deprecation头

### 19.3 版本切换

- URL版本：/api/v1/*、/api/v2/*
- 未指定版本：默认最新
- 客户端可显式指定

## 二十、接口的安全

### 20.1 传输安全

- 生产环境强制HTTPS
- TLS 1.2+

### 20.2 认证

- JWT在Authorization头
- 不在URL里传token

### 20.3 CORS

- 生产环境白名单
- 不用 *

### 20.4 CSRF

- 使用JWT而非Cookie，天然防CSRF
- 如用Cookie，需CSRF token

### 20.5 输入校验

- 所有输入按接口声明的schema校验
- 不信任客户端
- SQL参数化

### 20.6 输出过滤

- 敏感字段脱敏
- 错误信息不泄露内部细节

### 20.7 请求大小限制

- 默认1MB
- 文件上传单独处理

### 20.8 超时

- 客户端超时：30秒
- 服务端处理：30秒
- 长任务异步返回
