二、部署形态

2.1 支持的部署形态

形态 说明 适用
单机部署 一台服务器跑全部 个人使用、小规模
前后端分离 前端静态托管，后端 API 中规模
容器部署 Docker / Docker Compose 标准化
云托管 云服务器 / 云数据库 生产环境
混合 部分组件云服务 按需

2.2 推荐部署形态

第一推荐：Docker Compose 单机部署

· 简单
· 可移植
· 一键启动
· 适合个人和中小规模

第二推荐：云服务器 + 云数据库

· 稳定
· 可扩展
· 适合生产

备选：apt + pip 手动安装

· 无 Docker 的环境使用，Termux（Android）场景只走这一条
· 系统依赖用 apt 安装，Python 依赖用 pip 安装到虚拟环境
· 依赖管理与升级需自行维护

2.3 部署组件

组件 说明 必需
应用进程 FastAPI + 引擎 是
数据库 PostgreSQL / SQLite 是
反向代理 Nginx / Caddy 推荐
前端静态 Nginx 托管 是
监控 Prometheus + Grafana 推荐
日志 Loki / ELK 可选
备份 对象存储 / 本地 推荐
缓存 Redis 可选

2.4 最小部署

· 1 台服务器（2 核 4G）
· SQLite
· Nginx
· 应用进程

2.5 推荐部署

· 1 台应用服务器（4 核 8G）
· 1 台数据库（2 核 4G，PostgreSQL）
· 1 台 Nginx（1 核 2G）
· 对象存储（备份）
· 监控

2.6 大规模部署

· 多台应用服务器
· 数据库主从
· Redis 集群
· 负载均衡
· 分布式监控

三种形态的适用边界与升级路径：

| 形态 | 适用规模 | 升级到下一形态的触发条件 |
|---|---|---|
| 最小部署 | 单用户试用、功能验证 | 需要多用户并发访问，或需要在线备份 |
| 推荐部署 | 数十用户、千级实例 | 单机实例数接近容量上限，或需要不停机升级 |
| 大规模部署 | 多机多实例 | 已为终态，容量不足时继续按同一方式增加应用服务器 |

从最小到推荐：数据库由 SQLite 换为 PostgreSQL，纳入监控与对象存储备份。
从推荐到大规模：应用服务器由单台变为多台并加负载均衡，数据库加主从，缓存由单机换为集群，监控由单点采集换为分布式采集。

升级路径是单调的：不提供从推荐形态降回最小形态的操作，回退需通过备份恢复完成。

8.7 灰度升级

灰度用于降低升级风险：先让一部分流量或一部分用户跑新版本，确认无问题后再全量。

灰度维度：

| 维度 | 说明 |
|---|---|
| 按用户 | 先升少数用户，观察其告警与错误率 |
| 按实例 | 先升少数实例，观察实例恢复与下单链路 |
| 按机器 | 多机部署时先升一台应用服务器 |

灰度步骤：

1. 全量备份，确认备份可用
2. 选定灰度范围，记录该范围内的用户或实例清单
3. 升级灰度范围内的节点
4. 观察窗口内确认：健康检查通过、错误率无上升、对账差异无新增、实例恢复正常
5. 观察窗口内出现问题，按 8.5 回滚，只回滚灰度范围
6. 观察通过后按同一流程扩大到下一批，直至全量

约束：

· 灰度期间新旧版本的数据库结构必须兼容，迁移只做向后兼容的新增
· 新旧版本并存时，不改变已有的接口语义与数据格式
· 灰度范围必须可枚举、可回滚，不允许"升一半说不清哪些升了"
· 每批之间保留观察窗口，不在同一时间窗内连续扩大范围

13.2 水平扩展

· 多应用实例
· 负载均衡
· 共享数据库

适用于： 大规模。

挑战与对策：

| 挑战 | 对策 |
|---|---|
| 实例调度需分布式 | 按分片键确定归属，同一分片键始终落在同一引擎实例上 |
| 状态需共享 | 引擎实例之间只通过数据库共享状态，不直接互相调用 |
| 锁需分布式 | 锁按分片键加前缀，避免跨分片争用 |
| 账号连接不可复制 | 一个账号的连接与用户数据流只由归属它的引擎实例持有 |
| 全局风控需聚合 | 全局阈值跨引擎实例聚合，聚合口径以数据库为准 |
| 行情重复订阅 | 允许各引擎实例各自订阅同一交易对，不引入行情分片 |

扩容与缩容：

· 扩容时新增引擎实例，随后只能承接新的分片键，不自动迁移已有分片
· 缩容时先把待下线引擎实例上的实例停掉并完成对账，再把它持有的分片键重新分配
· 分片的迁移只在实例处于已停止状态时进行

扩容判据与后续核对见《运维手册》。

十六、常见故障处理

16.1 应用无法启动

原因 处理
配置错误 检查 .env
端口占用 换端口或杀进程
数据库不可用 检查数据库
密钥缺失 配置密钥
依赖缺失 安装依赖

16.2 实例无法启动

原因 处理
账号失效 更新密钥
策略缺失 检查策略文件或重新扫描扩展
插件绑定失效 重新安装插件或修复后恢复绑定
参数错误 修正参数
对账失败 手动对账

16.3 下单失败

原因 处理
余额不足 充值
限频 等待
账号失效 更新密钥
网络问题 重试

16.4 对账差异

原因 处理
网络丢包 重新对账
币安延迟 等待
本地 bug 修正

16.5 数据库故障

原因 处理
连接失败 检查网络
磁盘满 清理
数据损坏 从备份恢复

16.6 性能问题

原因 处理
CPU 高 优化查询
内存高 清理缓存
磁盘 IO 高 优化写入
网络慢 优化调用

16.7 安全问题

原因 处理
越权访问 封禁账号
爆破 封禁 IP
数据泄露 紧急处理
密钥泄露 更换密钥

16.8 故障的处理流程

```
1. 发现（监控/告警/用户）
2. 定位（日志/指标/审计）
3. 止损（降级/熔断/暂停）
4. 修复（重启/回滚/修正）
5. 验证（功能正常）
6. 复盘（原因/改进）
7. 记录（审计/文档）
```
