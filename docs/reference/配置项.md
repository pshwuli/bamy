# 配置项

> 本文档定义 BAMY 的全部配置项：名称、含义、类型、默认值、取值范围、生效方式、修改权限。
> 不写代码，只写配置契约。
> 本文档是完整设计，不是第一版，是最终态。

---

## 一、文档要回答的问题

1. 配置从哪来，谁覆盖谁
2. 有哪些配置项，各自什么含义
3. 每项的默认值和取值范围
4. 哪些配置改完要重启，哪些热生效
5. 扩展目录怎么配置，策略与插件各放哪里
6. 插件拦截与健康度有哪些全局参数
7. 哪些配置敏感，怎么保管
8. 谁有权改配置

## 二、配置来源与优先级

### 2.1 四个来源

| 来源 | 存放位置 | 优先级 | 生效方式 | 谁能改 |
|---|---|---|---|---|
| 环境变量 | 进程环境 / `.env` | 最高 | 重启 | 运维 |
| 配置文件 | `config/config.yaml` | 中 | 重启 | 运维 |
| 数据库配置 | 系统配置表 | 低 | 热更新（部分） | super_admin |
| 内置默认值 | 代码常量 | 最低 | 固定 | 不可改 |

### 2.2 覆盖规则

1. 高优先级来源一旦提供值，完全覆盖低优先级来源的同名项。
2. 高优先级不提供时，逐级向下取。
3. 覆盖发生在启动时一次性解析，运行中不重新解析环境变量。
4. 数据库配置的修改通过管理接口写入，立刻对相关模块生效。

### 2.3 解析失败的处理

| 情况 | 行为 |
|---|---|
| 必需项缺失 | 拒绝启动，进程退出并打印缺失项名称 |
| 值类型错误 | 拒绝启动，打印项名与期望类型 |
| 值超范围 | 拒绝启动，打印项名与合法区间 |
| 非必需项缺失 | 用默认值继续启动 |
| 密钥长度不足 | 拒绝启动，要求重新生成 |

## 三、环境变量

### 3.1 必需项

| 变量 | 含义 | 类型 | 要求 |
|---|---|---|---|
| `SECRET_KEY` | JWT 签名密钥 | 字符串 | 长度≥32，不得与示例值相同 |
| `ENCRYPT_KEY` | 敏感字段加密密钥 | 字符串 | 长度≥32，与 `SECRET_KEY` 不同 |
| `DATABASE_URL` | 数据库连接串 | 字符串 | 见 3.3 |
| `APP_ENV` | 运行环境 | 枚举 | `dev` / `prod` |

### 3.2 可选项

| 变量 | 含义 | 类型 | 默认值 | 取值范围 |
|---|---|---|---|---|
| `APP_NAME` | 应用名 | 字符串 | `BAMY` | 1-32 字符 |
| `APP_HOST` | 监听地址 | 字符串 | `0.0.0.0` | 合法 IPv4 |
| `APP_PORT` | 监听端口 | 整数 | `8000` | 1-65535 |
| `LOG_LEVEL` | 日志级别 | 枚举 | `info` | `debug` `info` `warning` `error` |
| `LOG_DIR` | 日志目录 | 路径 | `./logs` | 可写路径 |
| `ENABLE_LIVE_TRADING` | 是否允许实盘下单 | 布尔 | `false` | `true` `false` |
| `ACCESS_TOKEN_EXPIRE` | 访问 token 有效期（秒） | 整数 | `1800` | 60-86400 |
| `REFRESH_TOKEN_EXPIRE` | 刷新 token 有效期（秒） | 整数 | `604800` | 3600-2592000 |
| `ALLOW_REGISTER` | 是否允许注册 | 布尔 | `true` | `true` `false` |
| `ALLOW_EMAIL_REGISTER` | 是否允许邮箱注册 | 布尔 | `false` | `true` `false` |
| `ALLOW_INVITE_REGISTER` | 是否允许邀请码注册 | 布尔 | `false` | `true` `false` |
| `AUTO_RECOVER_ON_BOOT` | 崩溃后自动恢复实例 | 布尔 | `true` | `true` `false` |
| `RECOVER_CONCURRENCY` | 启动恢复并发数 | 整数 | `5` | 1-50 |
| `RECOVER_TIMEOUT` | 单实例恢复超时（秒） | 整数 | `60` | 5-600 |
| `RECONCILE_BEFORE_RECOVER` | 恢复前先对账 | 布尔 | `true` | `true` `false` |
| `RECONCILE_INTERVAL` | 定时对账间隔（秒） | 整数 | `30` | 5-3600 |
| `HEALTH_CHECK_INTERVAL` | 账号探活间隔（秒） | 整数 | `60` | 10-3600 |
| `MAX_INSTANCES_PER_USER` | 单用户实例数上限 | 整数 | `50` | 1-1000 |
| `EXTENSION_DIR` | 扩展根目录 | 路径 | `./extensions` | 可读路径 |
| `STRATEGY_DIR` | 策略目录 | 路径 | `./extensions/strategies` | 可读路径 |
| `PLUGIN_DIR` | 插件目录 | 路径 | `./extensions/plugins` | 可读路径 |
| `INIT_ADMIN_USER` | 初始管理员用户名 | 字符串 | 空 | 3-32 字符 |
| `INIT_ADMIN_PASS` | 初始管理员密码 | 字符串 | 空 | 满足密码规则 |

### 3.3 数据库连接串

| 环境 | 形态 |
|---|---|
| 生产 | `postgresql+asyncpg://<用户>:<密码>@<主机>:<端口>/<库名>` |
| 开发与小规模 | `sqlite+aiosqlite:///<路径>` |

要求：

- 连接串中的密码同样禁止写入版本库
- 生产环境必须使用独立数据库账号，不使用数据库超级用户
- 连接池参数在配置文件中设置，不写在连接串里

### 3.4 安全约束

以下变量在 `APP_ENV=prod` 时必须显式提供，缺失即拒绝启动：

- `SECRET_KEY`
- `ENCRYPT_KEY`
- `DATABASE_URL`

以下变量在 `APP_ENV=prod` 时取值为 `true` 会在启动日志中产生安全警告：

- `ALLOW_EMAIL_REGISTER`
- `ALLOW_INVITE_REGISTER`

## 四、配置文件

### 4.1 位置与格式

- 位置：`config/config.yaml`
- 格式：YAML
- 编码：UTF-8
- 缺失该文件时全部使用默认值，不报错

### 4.2 结构

```yaml
app:
  name: BAMY
  env: prod
  host: 0.0.0.0
  port: 8000

database:
  url: postgresql+asyncpg://user:pass@localhost/bamy
  pool_size: 20
  max_overflow: 10
  pool_timeout: 30

security:
  secret_key: xxx
  encrypt_key: xxx
  token_expire: 1800
  refresh_expire: 604800
  password_min_length: 8

engine:
  recover_concurrency: 5
  recover_timeout: 60
  reconcile_interval: 30
  health_check_interval: 60
  market_stale_threshold: 5

risk:
  max_orders_per_minute: 60
  max_orders_per_day: 1000
  max_daily_loss: 0.1
  max_drawdown: 0.3

monitor:
  enabled: true
  prometheus_port: 9090
  log_level: info

extensions:
  dir: ./extensions
  strategy_dir: ./extensions/strategies
  plugin_dir: ./extensions/plugins

plugins:
  intercept_timeout_ms: 200
  error_threshold: 10
  network_enabled: true
  max_per_checkpoint: 16
  max_hooks: 32
```

### 4.3 各段说明

| 段 | 作用 | 影响模块 |
|---|---|---|
| `app` | 应用标识与监听 | 接口模块 |
| `database` | 连接与连接池 | 数据层 |
| `security` | 密钥与 token 生命周期 | 用户模块 |
| `engine` | 恢复、对账、探活、行情新鲜度 | 引擎 |
| `risk` | 限频与风控阈值 | 风控模块 |
| `monitor` | 监控与日志 | 接口模块、审计模块 |
| `extensions` | 扩展根目录与两个子目录 | 策略中心、插件中心 |
| `plugins` | 插件拦截与健康度参数 | 插件中心 |

### 4.4 连接池参数

| 参数 | 默认值 | 说明 |
|---|---|---|
| `pool_size` | 20 | 常驻连接数 |
| `max_overflow` | 10 | 峰值可超出的连接数 |
| `pool_timeout` | 30 | 取连接等待上限（秒），超时即报错 |

连接池上限与实例数的关系：单实例不独占连接，按需借还。连接池耗尽时应快速失败并计入监控，不得无限等待。

### 4.5 扩展目录

扩展是磁盘上的加载单元，分策略包与插件包两类，各有自己的目录。

| 配置键 | 类型 | 默认值 | 说明 | 生效方式 |
|---|---|---|---|---|
| `extensions.dir` | 路径 | `./extensions` | 扩展根目录，仅用于定位两个子目录 | 重启生效 |
| `extensions.strategy_dir` | 路径 | `./extensions/strategies` | 策略目录，存放策略包 | 重启生效 |
| `extensions.plugin_dir` | 路径 | `./extensions/plugins` | 插件目录，存放插件包 | 重启生效 |

规则：

- 两个子目录都必须存在且可读，缺失时对应类型的扩展一个也加载不了。
- 目录内每个子目录是一个扩展，目录名即扩展 ID。
- 以 `__` 开头的子目录被跳过。
- 策略目录与插件目录不在同一命名空间，允许同名，但不建议。

### 4.6 插件参数

控制插件拦截链与健康度的全局上限。单项插件的 `timeout_ms` 可在其 `plugin.yaml` 的钩子声明里覆盖全局默认值。

| 配置键 | 类型 | 默认值 | 取值范围 | 说明 | 生效方式 |
|---|---|---|---|---|---|
| `plugins.intercept_timeout_ms` | 整数 | `200` | 1-2000 | 拦截型钩子的默认超时（毫秒） | 重启生效 |
| `plugins.error_threshold` | 整数 | `10` | 0-1000 | 插件连续异常自动停用阈值（次），0 表示不自动停用 | 重启生效 |
| `plugins.network_enabled` | 布尔 | `true` | `true` `false` | 插件出网是否全局允许 | 重启生效 |
| `plugins.max_per_checkpoint` | 整数 | `16` | 1-64 | 单个检查点上最多拦截插件数 | 重启生效 |
| `plugins.max_hooks` | 整数 | `32` | 1-128 | 单个插件最多钩子数 | 重启生效 |

其中超时与停用阈值两项在数据库配置表里有对应的热更新项，见第五节，管理员改完立刻生效，无需重启。

说明：

- `plugins.intercept_timeout_ms` 是全局默认值，上限 2000 毫秒；插件在钩子上声明的 `timeout_ms` 不能超过该上限。
- `plugins.error_threshold` 达到后，绑定自动置为 `disabled`、发布 `system.alert` 并记审计，需管理员手动恢复。
- `plugins.network_enabled` 为 `false` 时，所有插件一律禁止出网，即使插件声明了 `network` 段；该开关是全局总闸，单个插件的白名单不能绕过它。
- `plugins.max_per_checkpoint` 与 `plugins.max_hooks` 在加载时校验，超限的插件加载失败并提示，不影响其他插件。

## 五、数据库配置

### 5.1 存放内容

存于系统配置表，键值对形式，带类型、默认值、修改人、修改时间。

| 配置键 | 含义 | 默认值 | 热生效 |
|---|---|---|---|
| `register.enabled` | 是否开放注册 | true | 是 |
| `register.invite_only` | 是否仅邀请码注册 | false | 是 |
| `instance.max_per_user` | 单用户实例上限 | 50 | 是 |
| `account.max_per_user` | 单用户账号上限 | 20 | 是 |
| `instance.auto_recover` | 崩溃后自动恢复 | true | 是 |
| `order.max_per_minute` | 单账号每分钟下单上限 | 60 | 是 |
| `order.max_per_day` | 单账号每日下单上限 | 1000 | 是 |
| `risk.max_daily_loss` | 单日最大亏损比例 | 0.1 | 是 |
| `risk.max_drawdown` | 最大回撤比例 | 0.3 | 是 |
| `paper.default_fee_rate` | 模拟盘默认手续费率 | 0.001 | 是 |
| `paper.default_slippage` | 模拟盘默认滑点 | 0.0005 | 是 |
| `paper.snapshot_interval` | 模拟盘快照间隔（秒） | 60 | 是 |
| `plugin.intercept_timeout_ms` | 拦截型钩子默认超时（毫秒） | 200 | 是 |
| `plugin.auto_disable_threshold` | 插件连续异常自动停用阈值（次） | 10 | 是 |
| `plugin.max_per_user` | 单用户插件绑定数上限 | 20 | 是 |

### 5.2 修改约束

- 只有 `super_admin` 可修改
- 每次修改写审计日志，记录旧值、新值、修改人、时间
- 修改后在页面与接口上立刻生效，不需要重启
- 已创建的实例不追溯变更，只影响后续动作

## 六、生效方式汇总

| 配置来源 | 生效方式 | 是否需要重启 |
|---|---|---|
| 环境变量 | 启动时解析一次 | 是 |
| 配置文件 | 启动时解析一次 | 是 |
| 数据库配置 | 每次读取时查缓存 | 否，热更新 |
| 内置默认值 | 固定 | 不适用 |

需要重启才能生效的配置，在管理员页面上标注"重启生效"。

## 七、敏感配置

### 7.1 清单

| 配置 | 敏感级别 | 处理方式 |
|---|---|---|
| `SECRET_KEY` | 高 | 仅环境变量或密钥管理工具注入 |
| `ENCRYPT_KEY` | 高 | 仅环境变量或密钥管理工具注入 |
| `DATABASE_URL` | 高 | 密码部分不入版本库 |
| 币安 API 密钥 | 高 | 加密后存库，绝不出现在配置与日志 |
| 插件设置中的 secret 字段 | 高 | 加密后存库，只在本插件绑定内可见 |
| 初始管理员密码 | 中 | 首次启动后立即修改 |

### 7.2 规则

- 密钥、密码不出现在配置文件明文里
- 密钥、密码不出现在日志、错误响应、页面
- 接口返回敏感字段时一律脱敏，只显示前 4 位与后 4 位
- 版本库中的示例配置只写占位符 `xxx`
