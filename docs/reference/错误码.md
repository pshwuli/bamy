# 错误码

> 本文档定义 BAMY 的全部错误码：编号规则、每一段的含义、每个错误码的触发条件与处理建议。
> 不写代码，只写契约。
> 本文档是完整设计，不是第一版，是最终态。

---

## 一、文档要回答的问题

1. 错误码怎么编号
2. 有哪些错误码段
3. 每个错误码在什么情况下出现
4. 每个错误码该由谁处理、怎么处理
5. 错误码和 HTTP 状态码是什么关系
6. 命名错误码与编号是什么关系
7. 错误码如何演进

## 二、编号规则

### 2.1 基本公式

```
错误码 = HTTP 状态码 × 1000 + 段内序号
```

示例：`40001` = HTTP 400 + 序号 001。

### 2.2 分段

| 段 | 对应 HTTP 状态 | 含义 | 处理方 |
|---|---|---|---|
| 400xx | 400 | 请求参数错误 | 调用方修正请求 |
| 401xx | 401 | 认证失败 | 调用方重新登录 |
| 403xx | 403 | 授权失败 | 调用方换身份或放弃 |
| 404xx | 404 | 资源不存在 | 调用方检查标识 |
| 409xx | 409 | 状态冲突 | 调用方先改变状态 |
| 422xx | 422 | 业务校验失败 | 调用方修正业务条件 |
| 429xx | 429 | 请求过频 | 调用方退避后重试 |
| 500xx | 500 | 服务端内部错误 | 管理员介入 |
| 502xx | 502 | 外部依赖错误 | 系统自动重试、必要时告警 |
| 503xx | 503 | 服务不可用 | 等系统恢复 |
| 504xx | 504 | 外部依赖超时 | 系统自动对账收敛 |

### 2.3 成功码

| 码 | 含义 |
|---|---|
| `0` | 成功 |

### 2.4 命名错误码

插件拦截类错误码除了编号之外，还发布一个稳定的英文名（如 `PLUGIN_DENIED`）。两种表达指向同一个码：

| 表达 | 用途 |
|---|---|
| 英文名 | 稳定标识，跨模块引用、审计记录、插件文档中使用 |
| 编号 | 接口传输形式，出现在响应的 `code` 字段中 |

规则：

- 英文名与编号一一对应，同时发布、同时废弃。
- 英文名全大写，词间用下划线。
- 调用方按编号判断，日志与审计中两种写法都可出现。

### 2.5 命名与演进

- 错误码一旦发布，语义不再改变。
- 废弃的错误码不回收，不再返回。
- 新增错误码只能追加段内序号，不插队、不重排。
- 错误码是稳定契约，调用方按码判断，不按 message 字符串判断。

## 三、响应中的位置

```json
{
  "code": 40001,
  "message": "参数错误",
  "data": null,
  "request_id": "xxx",
  "timestamp": 1690000000000
}
```

| 字段 | 说明 |
|---|---|
| `code` | 错误码，成功为 0 |
| `message` | 面向人的简述，可本地化，不作为判断依据 |
| `data` | 失败时为 `null`，或承载字段级错误详情 |
| `request_id` | 用于日志追踪与问题定位 |
| `timestamp` | 服务端时间 |

字段级错误放在 `data` 中：

```json
{
  "code": 42201,
  "message": "业务校验失败",
  "data": {
    "field": "params.grid_count",
    "reason": "超出范围"
  }
}
```

## 四、400xx 请求参数错误

| 错误码 | 含义 | 触发条件 | 调用方应对 |
|---|---|---|---|
| 40001 | 参数错误 | 请求体格式非法、JSON 解析失败 | 修正格式 |
| 40002 | 参数类型错误 | 字段类型与 schema 不符 | 修正类型 |
| 40003 | 参数范围错误 | 数值超出声明区间 | 修正取值 |
| 40004 | 必填参数缺失 | 缺少必填字段 | 补齐字段 |
| 40005 | 参数依赖不满足 | A 字段必须与 B 字段同时出现或互斥 | 调整组合 |

## 五、401xx 认证失败

| 错误码 | 含义 | 触发条件 | 调用方应对 |
|---|---|---|---|
| 40101 | 未登录 | 未携带凭证访问受保护接口 | 先登录 |
| 40102 | Token 无效 | 签名错误、被撤销、格式非法 | 重新登录 |
| 40103 | Token 过期 | 超过有效期 | 用刷新 token 换新 |
| 40104 | 用户名或密码错误 | 登录凭证不匹配 | 重新输入 |
| 40105 | 账号被锁定 | 连续失败达到锁定阈值 | 等待解锁 |
| 40106 | 账号被禁用 | 管理员已禁用该用户 | 联系管理员 |
| 40107 | 二次验证失败 | 2FA 验证码错误或已用 | 重新获取验证码 |
| 40108 | 二次验证未完成 | 已通过密码但未过 2FA | 完成 2FA |
| 40109 | 邀请码无效 | 邀请码不存在、过期、已用尽 | 索取新邀请码 |
| 40110 | 邮箱未验证 | 账号处于待验证状态 | 完成邮箱验证 |

## 六、403xx 授权失败

| 错误码 | 含义 | 触发条件 | 调用方应对 |
|---|---|---|---|
| 40301 | 无权限 | 当前角色不满足接口要求 | 放弃或换身份 |
| 40302 | 角色不足 | 需要更高角色 | 请管理员授权 |
| 40303 | 被隔离（返回 404 伪装） | 访问他人资源时，为防枚举返回不存在 | 不区分处理 |
| 40304 | 仅只读 | 访客 token 试图执行写操作 | 改用登录身份 |
| 40305 | 分享 token 超出绑定范围 | 访问非该 token 绑定的实例 | 检查 token 绑定 |

说明：`40303` 在响应上以 404 呈现，用于避免通过错误差异推断资源是否存在。

## 八、409xx 状态冲突

| 错误码 | 含义 | 触发条件 | 调用方应对 |
|---|---|---|---|
| 40901 | 资源冲突 | 唯一字段重复，如用户名、实例名 | 换一个取值 |
| 40902 | 状态冲突 | 当前状态不允许该操作 | 先变更到允许的状态 |
| 40903 | 实例正在运行 | 对运行中实例执行删除或换策略 | 先停止 |
| 40904 | 实例已有持仓 | 有持仓时执行换策略或删除 | 先平仓 |
| 40905 | 账号正在被实例使用 | 删除仍被引用的账号 | 先停用相关实例 |
| 40906 | 账号已失效 | 密钥失效，禁止启动相关实例 | 更新密钥 |
| 40907 | 实例数已达上限 | 超过单用户实例数上限 | 删除闲置实例或申请提额 |
| 40908 | 账号数已达上限 | 超过单用户账号数上限 | 删除闲置账号或申请提额 |
| 40909 | 策略正在被使用 | 卸载仍被实例引用的策略 | 先切换实例策略 |
| 40910 | 熔断中 | 已触发熔断，禁止开仓 | 等待解除或联系管理员 |
| 40911 | 冷却中 | 命中单币或策略冷却期 | 等待冷却结束 |
| 40912 | 对账未通过 | 差异未收敛，禁止恢复交易 | 等待对账完成 |
| 40913 | 绑定已存在 | 该作用域上已有同一插件的绑定，且插件声明 `allow_multiple` 为 false | 改用修改已有绑定 |
| 40914 | 绑定被自动停用 | 连续异常超阈值，绑定已置为 `disabled` | 排查后由管理员恢复 |
| 40915 | 插件绑定数已达上限 | 超过 `plugin.max_per_user` | 删除闲置绑定或申请提额 |

## 九、422xx 业务校验失败

### 9.1 通用

| 错误码 | 含义 | 触发条件 |
|---|---|---|
| 42201 | 业务校验失败 | 通过格式校验但不满足业务规则 |

|---|---|---|
| 42210 | API 密钥无效 | 交易所拒绝该密钥 |

| 42213 | 账号探活失败 | 定时探活请求失败 |

| 错误码 | 含义 | 触发条件 |
|---|---|---|
| 42220 | 策略加载失败 | 元信息或代码解析失败 |

| 错误码 | 含义 | 触发条件 |

### 9.9 插件绑定

| 错误码 | HTTP 状态码 | 含义 | 触发条件 |
|---|---|---|---|
| 42280 | 422 | 绑定作用域非法 | `scope` 取值不在 `global` / `user` / `account` 内，或 `scope_id` 与 `scope` 不匹配 |
| 42281 | 422 | 不允许创建全局绑定 | 非管理员试图创建 `global` 级绑定 |
| 42282 | 422 | 不允许安装全系统数据范围的插件 | 插件的 `data_scope` 为 `all`，由非管理员发起安装 |
| 42283 | 422 | 绑定已失效 | 引用的插件未加载成功或已卸载，绑定被置为 `invalid` |

逐条说明：

| 错误码 | 常见原因 | 处理建议 | 前端建议 |
|---|---|---|---|
| 42280 | 请求里的 `scope_id` 与 `scope` 不配套，如 `scope` 为 `user` 却填了账号 ID；`scope` 取值拼写错误 | 按三级作用域的对应关系重填：`global` 无 `scope_id`，`user` 填用户 ID，`account` 填账号 ID | 不让用户手填作用域与 ID：作用域由入口决定，ID 从当前上下文带入；报错时高亮作用域字段并说明三者对应关系 |
| 42281 | 用户端页面误显示了全局安装入口，或接口被直接调用 | 全局绑定的入口只对管理员开放；确认前端按角色渲染入口 | 非管理员不渲染全局绑定入口；直接调用时提示"全局插件只能由管理员安装"，并给出用户级绑定或账号级绑定的替代入口 |
| 42282 | 用户试图安装声明 `data_scope: all` 的插件 | 该类插件只允许管理员安装；用户端应在市场列表里直接不提供安装按钮 | 在插件市场对 `data_scope` 为 `all` 的插件显著标注"仅管理员可安装"，隐藏用户的安装按钮；直连接口时提示原因与替代方案 |
| 42283 | 插件文件被删除、加载失败，或管理员卸载了插件 | 修好插件文件后触发重新扫描扩展，绑定会恢复为可用；不再需要时删除绑定 | 在绑定列表里标记为"已失效"并给出失效原因，禁用其启停开关，提供重新扫描与删除两个动作 |

### 9.10 插件拦截（命名错误码）

插件在检查点上拦截产生的统一错误码，与《插件规范》第 6.6 节一致。

| 错误码 | 英文名 | HTTP 状态码 | 含义 |
|---|---|---|---|
| 42290 | `PLUGIN_DENIED` | 422 | 被插件拒绝 |
| 42291 | `PLUGIN_TIMEOUT` | 422 | 插件拦截超时且 `fail_mode` 为拒绝 |
| 42292 | `PLUGIN_ERROR` | 422 | 插件拦截时抛异常且 `fail_mode` 为拒绝 |

逐条说明：

| 错误码 | 常见原因 | 处理建议 | 前端建议 |
|---|---|---|---|
| 42290 | 插件按自定义规则否决了请求，如禁止该交易对、禁止大额开仓、锁定仓位禁止平仓、参数不符合合规要求 | 属于插件的正常业务判断，系统不重试；在审计中查 `plugin_id` 与 `reason`，需要调整时改绑定设置或停用绑定 | 提示被哪个插件拒绝并原样附上 `reason`，如"被插件 Telegram 通知拒绝：禁止该交易对"；提示用户如何调整（改设置或请管理员处理），不提示"重试" |
| 42291 | 插件处理函数耗时超过声明的 `timeout_ms`（默认 200 毫秒），如内部串行调用了慢速外部服务 | 检查该插件的平均耗时与最近错误；调大 `timeout_ms`（上限 2000 毫秒）或把耗时动作移出拦截链 | 提示"插件响应超时，操作已被拒绝"，附插件名；说明这是插件侧 `fail_mode` 为拒绝所致，不是系统故障；提供去绑定详情页看健康度的入口 |
| 42292 | 插件处理函数抛异常，或返回了非法结论（非 `ALLOW` / `DENY` / `MODIFY`） | 由插件作者修复代码后重新扫描扩展；连续异常达阈值时绑定会被自动停用 | 提示"插件执行出错，操作已被拒绝"，附插件名与错误摘要；管理员端提示可查看健康度并手动恢复或停用该绑定 |

响应 `data` 中同时给出定位字段：

| 字段 | 说明 |
|---|---|
| `plugin_id` | 拒绝发生的插件 |
| `binding_id` | 生效的绑定 |
| `effective_scope` | 实际生效的作用域 |
| `reason` | 插件给出的拒绝原因，`PLUGIN_DENIED` 时必有 |
| `checkpoint` | 发生的检查点 |

`PLUGIN_DENIED`、`PLUGIN_TIMEOUT`、`PLUGIN_ERROR` 三者只在拦截型钩子上产生。订阅型钩子出错不影响调用方，不返回错误码。

### 9.11 拦截错误码在各检查点的表现

| 检查点 | 拒绝后的表现 |
|---|---|
| `instance.before_start` | 实例不启动，状态置 `error`，`last_error` 写明被哪个插件拒绝 |
| `order.before_submit` | 下单不发出，订单记为 `rejected`，来源标记为插件拦截 |
| `position.before_close` | 平仓不执行，返回拒绝原因给调用方 |
| `params.before_save` | 参数不落库，返回拒绝原因给用户 |

拦截结论按 `fail_mode` 分叉：`fail_mode` 为放行时，插件超时与异常都不产生错误码，只记日志、计数与告警。

## 十一、500xx 服务端内部错误

| 错误码 | 含义 | 触发条件 | 处理 |
|---|---|---|---|
| 50001 | 内部错误 | 未捕获异常 | 记录堆栈，管理员介入 |
| 50002 | 数据库错误 | 查询或写入失败 | 记录并告警 |
| 50003 | 外部服务错误 | 依赖服务返回异常 | 记录并告警 |
| 50004 | 配置错误 | 配置缺失或非法 | 修正配置后重启 |
| 50005 | 加密或解密失败 | 密钥不匹配或数据损坏 | 管理员介入，检查密钥 |

## 十二、502xx / 504xx 外部依赖

| 错误码 | 含义 | 触发条件 | 处理 |
|---|---|---|---|
| 50201 | 交易所接口错误 | 交易所返回业务错误 | 映射为对应业务码或重试 |
| 50202 | 交易所返回不可解析 | 响应结构变化 | 记录原始响应并告警 |
| 50203 | 行情源不可用 | 行情连接断开 | 切备用源，或停止开仓 |
| 50204 | 通知渠道失败 | 告警推送失败 | 记录并降级到备用渠道 |
| 50401 | 交易所请求超时 | 超过请求超时上限 | 进入对账队列 |
| 50402 | 数据库请求超时 | 超过语句超时上限 | 记录并告警 |

## 十三、503xx 服务不可用

| 错误码 | 含义 | 触发条件 | 处理 |
|---|---|---|---|
| 50301 | 服务不可用 | 系统启动中、关闭中、过载 | 稍后重试 |
| 50302 | 只读模式 | 数据库不可写时的降级 | 稍后重试 |
| 50303 | 引擎未就绪 | 引擎启动未完成 | 等健康检查通过 |

## 十四、错误码与内部分类的关系

内部分类（见《异常与容错》）与外发错误码的映射：

| 内部来源 | 影响范围 | 外发表现 |
|---|---|---|
| 参数异常 | 单次请求 | 400xx |
| 认证异常 | 单次请求 | 401xx |
| 权限异常 | 单次请求 | 403xx |
| 业务校验异常 | 单次请求 | 422xx |
| 插件拦截拒绝 | 单次请求 | 4229x，附 `plugin_id` 与 `reason` |
| 状态机异常 | 单次请求 | 409xx |
| 交易所业务拒绝 | 单次请求 | 422xx 或 502xx |
| 交易所不可达 | 单账号 | 502xx / 504xx，并触发探活 |
| 数据库不可用 | 全局 | 503xx，进入只读或熔断 |
| 未捕获异常 | 单次请求 | 500xx |

内部异常码与外部错误码不是一一对应：多个内部异常可能映射到同一外发码，映射关系由接口层统一收口。
