# 运维手册

> 本文档定义 BAMY 的日常运维动作：每天看什么、每周做什么、每月做什么，以及备份、恢复、升级、扩容的标准步骤。
> 面向部署与维护本系统的人。设计与规则见《部署与运行》，本文档只讲怎么做、多久做一次、做到什么程度算合格。
> 本文档是完整设计，不是第一版，是最终态。

---

## 一、适用场景

- 系统已部署并在运行，需要维持其稳定
- 要按周期巡检、备份、升级、扩容
- 要在故障发生时按流程处置

故障的定位与处置细节见《故障处理》，本文档负责常态运维。

---

## 二、前置条件

| 项 | 要求 |
|---|---|
| 部署 | 已按《部署与运行》完成部署并通过安装验证 |
| 权限 | 具备服务器、数据库、监控的运维权限 |
| 密钥 | `SECRET_KEY`、`ENCRYPT_KEY` 已单独保管，且不在日志与页面出现 |
| 监控 | 指标采集与告警渠道已接好 |
| 备份 | 定时备份任务已启用并有失败告警 |

## 三、日常巡检

### 3.1 每日检查

| 检查项 | 怎么看 | 合格标准 |
|---|---|---|
| 系统健康 | 健康检查端点 | 返回正常 |
| 实例状态 | 实例列表 | 无实例停在出错态超过预期时长 |
| 账号状态 | 账号列表 | 无账号处于失效或异常态而未处理 |
| 订单异常 | 订单列表筛选失败与未知 | 未知状态订单在较短时间内被对账收敛 |
| 对账差异 | 对账差异列表 | 无新增未解决差异，或差异已在处理 |
| 告警 | 告警渠道 | 无未确认告警 |
| 备份结果 | 备份任务日志 | 昨日全量与最近增量均成功 |
| 日志错误 | 应用日志筛错误级别 | 无持续重复的新错误 |

### 3.2 每周检查

| 检查项 | 目的 |
|---|---|
| 备份可恢复性 | 抽查一次备份，实际恢复到临时库并核对记录数 |
| 日志分析 | 找重复出现的错误与慢请求，判断是否需要处理 |
| 性能趋势 | 看 CPU、内存、连接数、对账队列长度的走向 |
| 安全审计 | 查登录失败次数、越权访问次数、异常来源地址 |
| 磁盘水位 | 确认日志与备份未把磁盘写满 |

### 3.3 每月检查

| 检查项 | 目的 |
|---|---|
| 依赖更新 | 评估运行环境与第三方库的安全更新 |
| 系统更新 | 操作系统补丁 |
| 容量规划 | 按实例数、订单量的增长判断是否需要扩容 |
| 恢复演练 | 完整走一遍恢复流程并记录耗时 |
| 密钥轮换评估 | 判断是否需要更换 JWT 与加密密钥 |

## 四、启停与重启

### 4.1 启动顺序

1. 数据库就绪
2. 服务进程启动
3. 健康检查通过
4. 引擎初始化
5. 按配置执行崩溃恢复：先对账，再逐个恢复实例

### 4.2 启动检查

| 检查 | 期望 |
|---|---|
| 必需配置齐全 | 缺任何一项直接拒绝启动 |
| 数据库可连 | 连接池建立成功 |
| 迁移版本一致 | 库结构版本与代码期望一致 |
| 健康检查 | 通过 |
| 恢复日志 | 每个被恢复实例都有明确结果 |

启动是幂等的：重复启动不会重复创建管理员，也不会重复恢复已在运行的实例。

### 4.3 优雅停止

1. 收到停止信号
2. 停止接受新请求
3. 停止实例：取消行情订阅、调用策略停止回调、按配置决定是否平仓
4. 等待进行中的下单与对账收尾
5. 关闭连接池
6. 进程退出

优雅停止有超时上限，超时后转入强制停止。强制停止可能留下未收敛的订单，重启后由对账补齐。

### 4.4 重启

- 计划内重启：先优雅停止，再启动，期间实例短暂中断
- 重启后先对账再恢复，避免用本地旧状态继续交易
- 大范围重启前，建议先手动停止对时效敏感的实例

## 五、备份

### 5.1 备份内容与频率

| 内容 | 频率 | 保留 |
|---|---|---|
| 数据库全量 | 每天 | 7 天 |
| 数据库增量 | 每小时 | 24 小时 |
| 配置文件 | 变更时 | 30 天 |
| 加密密钥 | 变更时 | 永久 |
| 插件目录 | 变更时 | 30 天 |
| 日志 | 每天 | 30 天 |

### 5.2 备份方式

| 方式 | 适用 |
|---|---|
| 本地备份 | 快速回滚 |
| 远程备份 | 防单机故障，异地存放 |
| 对象存储 | 长期留存 |
| 冷备份 | 离线归档 |

至少保留一份异地备份。

### 5.3 备份的验证

- 每次全量备份后校验文件完整性
- 每周抽查一次，实际恢复到临时库
- 核对用户数、账号数、实例数、订单数、审计记录数
- 记录验证结果，失败即告警

### 5.4 备份的加密与保管

- 备份文件加密后存放
- 加密密钥与备份文件分开保管
- 备份文件不得包含明文密钥

### 5.5 备份的自动化

- 定时任务驱动，不依赖人工触发
- 失败立即告警，成功可每日汇总通知
- 备份任务本身计入监控，长时间未跑出即告警

## 六、恢复

### 6.1 恢复场景

| 场景 | 手段 |
|---|---|
| 数据损坏 | 从最近可用备份恢复 |
| 误删除 | 从备份恢复，或按审计记录重建 |
| 系统崩溃 | 重启并让框架对账恢复 |
| 灾难 | 异地备份恢复 |

### 6.2 恢复流程

```
1. 停止服务
2. 先备份当前数据（防止误操作扩大损失）
3. 恢复数据库
4. 恢复配置
5. 恢复密钥
6. 恢复插件目录
7. 启动服务
8. 验证
```

第 5 步不可省略：加密密钥若与数据不匹配，已加密的账号密钥将无法解密。

### 6.3 恢复的验证

| 项目 | 期望 |
|---|---|
| 用户数 | 与备份时一致 |
| 账号数 | 与备份时一致 |
| 实例数 | 与备份时一致 |
| 订单数 | 与备份时一致 |
| 审计完整性 | 关键操作记录连续，无断档 |
| 账号可解密 | 抽样验证账号密钥可正常解密使用 |
| 实例可启动 | 抽样启动实例，确认能进入运行态 |

### 6.4 目标指标

| 指标 | 目标 |
|---|---|
| 恢复时间 | 小于 1 小时 |
| 数据丢失窗口 | 小于 1 小时 |

### 6.5 演练

- 按周期做一次完整恢复演练
- 记录实际耗时与遇到的问题
- 演练后更新流程，不把演练结论只留在个人记忆里

## 七、升级

### 7.1 升级前

1. 读变更说明，确认有无破坏性变更
2. 确认数据库迁移是否需要停机
3. 完成一次全量备份并验证可用
4. 通知相关用户实例会短暂中断

### 7.2 升级步骤

```
1. 停止服务（优雅停止）
2. 备份数据库与配置
3. 拉取新版本代码
4. 安装新依赖
5. 执行数据库迁移
6. 构建前端
7. 启动服务
8. 验证
```

### 7.3 数据库迁移

- 迁移只向前，回滚依靠备份而非逆向迁移
- 迁移前必须有可用备份
- 迁移脚本应在预发环境先跑一遍

### 7.4 回滚

1. 停止新版本服务
2. 恢复旧版本代码
3. 从备份恢复数据库
4. 启动并验证

回滚会丢失升级后产生的数据，因此升级窗口应选在业务低谷。

### 7.5 升级后验证

| 项目 | 期望 |
|---|---|
| 健康检查 | 通过 |
| 登录 | 可用 |
| 插件加载 | 无新增失败项 |
| 实例恢复 | 按配置正确恢复 |
| 对账 | 无异常差异 |
| 订单链路 | 模拟盘下单成功 |

## 八、监控与告警

### 8.1 监控层次

| 层次 | 看什么 |
|---|---|
| 主机 | CPU、内存、磁盘、网络 |
| 数据库 | 连接数、慢查询、锁等待 |
| 应用 | 请求量、错误率、响应时间 |
| 引擎 | 行情延迟、事件队列、下单队列、对账队列、限频余量、熔断次数 |
| 业务 | 实例数、账号数、订单数、成交额、盈亏 |
| 安全 | 登录失败次数、越权访问次数、异常来源 |

### 8.2 关键指标阈值

| 指标 | 告警方向 |
|---|---|
| 行情延迟 | 超过阈值即停止开仓并告警 |
| 对账队列长度 | 持续增长说明收敛不畅 |
| 限频余量 | 逼近上限说明下单过密 |
| 未知状态订单数 | 长时间不下降说明对账有问题 |
| 账号失效数 | 出现即需处理 |
| 熔断次数 | 短时间多次触发须排查 |
| 磁盘水位 | 达到高位线即清理日志与备份 |

### 8.3 告警渠道

按严重程度分级，渠道与分级规则见《异常与容错》。告警必须有人接收，无人接收的告警等同于没有监控。

## 九、日志

### 9.1 日志类型

| 类型 | 内容 |
|---|---|
| 应用日志 | 请求、错误 |
| 引擎日志 | 调度、下单、对账 |
| 业务日志 | 用户操作、订单 |
| 审计日志 | 安全与关键操作 |
| 访问日志 | HTTP 访问 |

### 9.2 日志规范

- 结构化输出，含时间、级别、模块、消息、上下文
- 关键字段带 `request_id`、`user_id`、`instance_id`，便于串联一次完整动作
- 日志中不得出现明文密钥、密码、完整账号密钥

### 9.3 日志轮转与保留

- 按大小与时间双重触发轮转
- 到期日志归档后清理，不做无限堆积
- 审计日志的保留期长于应用日志

## 十、容量与扩容

### 10.1 垂直扩展

优先加 CPU 与内存。行情分发、事件总线、对账都吃 CPU，实例数多时内存占用主要来自行情缓存与上下文。

### 10.2 扩容判据

| 信号 | 说明 |
|---|---|
| 事件队列持续积压 | 处理能力不足 |
| 对账队列收敛变慢 | 调度或外部调用成为瓶颈 |
| 数据库连接池频繁等待 | 需要调整池或扩库 |
| 内存持续攀升不回落 | 可能存在泄漏，先排查再扩容 |

### 10.3 数据库扩展

- 先优化索引与慢查询
- 再考虑读写分离
- 最后才考虑分库分表

### 10.4 扩容后的核对

扩容后必须重新核对：指标是否恢复、队列是否消化、实例是否全部恢复正常态。

## 十一、安全加固

### 11.1 常规动作

| 项目 | 动作 |
|---|---|
| 系统 | 最小化安装，关闭无用端口与服务 |
| 应用 | 生产禁用调试，强制 HTTPS，设置跨域白名单 |
| 数据库 | 不用超级用户连接，限制来源地址，定期改密 |
| 网络 | 只暴露必要端口，管理入口限来源 |
| 密钥 | 定期轮换，轮换后验证已加密数据仍可解密 |

### 11.2 密钥轮换注意事项

更换加密密钥属于高风险操作：旧数据用旧密钥加密，必须制定兼容方案，不可直接替换。轮换前先备份，轮换后在非生产环境验证解密路径。

### 11.3 访问审计

- 管理员的高危操作全部留痕
- 定期查看越权访问记录
- 离职与角色变更后立刻调整权限并撤销会话

## 十三、常见问题

| 问题 | 处理 |
|---|---|
| 服务起不来 | 先看是否缺必需配置，再看迁移版本是否一致，见《故障处理》 |
| 实例全部没恢复 | 检查自动恢复开关与恢复并发数，查看恢复日志 |
| 备份任务静默失败 | 为备份任务本身配置监控，长时间未成功即告警 |
| 恢复后账号密钥不可用 | 加密密钥与数据不匹配，须用与备份同期的密钥 |
| 磁盘被日志写满 | 缩短保留期、加密轮转，并检查是否有日志风暴 |
| 告警无人处理 | 明确接收人与升级路径，否则监控形同虚设 |
