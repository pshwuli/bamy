# 快速开始

> 本文档教从零把 BAMY 跑起来并完成第一笔模拟盘交易：装什么、配什么、点什么、看到什么算成功。
> 适用于第一次接触本系统的人。
> 本文档是完整设计，不是第一版，是最终态。

---

## 一、适用场景

- 第一次在本机或服务器把 BAMY 跑起来
- 想在不碰实盘的前提下，用模拟盘验证一套配置是否可用
- 想确认环境依赖是否齐全

部署与运维的完整内容见《部署与运行》，本文档只走通最短路径。

---

## 二、前置条件

### 2.1 机器要求

| 项 | 最低 | 推荐 |
|---|---|---|
| CPU | 2 核 | 4 核 |
| 内存 | 4GB | 8GB |
| 磁盘 | 20GB | 50GB SSD |
| 系统 | 主流 Linux | 同类 |

### 2.2 软件要求

| 方式 | 需要 |
|---|---|
| Docker 方式（推荐） | Docker 与 Docker Compose |
| 手动方式 | Python 3.11 及以上、Node.js 18 及以上、PostgreSQL 14 及以上 |

### 2.3 你需要准备好的东西

| 项 | 说明 | 是否必须 |
|---|---|---|
| 数据库 | PostgreSQL，或开发场景用 SQLite | 是 |
| 两个密钥 | JWT 签名密钥与字段加密密钥，各 32 位以上随机字符串 | 是 |
| 币安 API 密钥 | 只有要看实盘时才需要 | 否 |

第一笔模拟盘交易不需要任何交易所密钥。

## 三、安装

### 3.1 Docker Compose 方式

1. 确认 Docker 可用：

```
docker --version
docker compose version
```

2. 取得代码，进入项目根目录。

3. 复制配置模板：

```
cp .env.example .env
```

4. 生成两个密钥并写进 `.env`。每个密钥用独立的随机值，不要复用 `SECRET_KEY`：

```
openssl rand -hex 32
```

5. 编辑 `.env`，至少确认这几项：

| 变量 | 说明 |
|---|---|
| `SECRET_KEY` | JWT 签名密钥 |
| `ENCRYPT_KEY` | 加密密钥，与上一项不同 |
| `DATABASE_URL` | 数据库连接串 |
| `APP_ENV` | 首次试跑可用 `dev`，生产用 `prod` |
| `ENABLE_LIVE_TRADING` | 保持 `false` |
| `APP_PORT` | 默认 8000 |

6. 启动：

```
docker compose up -d
```

7. 确认启动成功：

```
docker compose ps
curl http://localhost:8000/health
```

### 3.2 手动方式

1. 安装 Python、Node、PostgreSQL。

2. 建虚拟环境并装后端依赖。

3. 装前端依赖并构建前端。

4. 配置 `.env`，内容同上一节的表。

5. 初始化数据库，让框架建表。

6. 启动后端进程。

7. 让 Nginx 托管前端静态文件并反向代理到后端。

详细命令与进程管理见《部署与运行》。

## 四、创建第一个管理员

1. 打开 `http://<主机>:<端口>/setup`。

2. 该系统只在"库中没有任何用户"时开放此页面。

3. 填写用户名与密码，密码须满足密码规则。

4. 提交后，系统创建第一个超级管理员，并自动关闭 `/setup`。

5. 若设置了 `INIT_ADMIN_USER` 与 `INIT_ADMIN_PASS`，首次启动就会创建管理员，无需访问 `/setup`。

6. 立刻用正常登录页登录一次，确认账号可用，随后修改初始密码。

`/setup` 关闭后不可再次访问。若确需新建管理员，由现有超级管理员在后台指定。

---

## 五、第一次登录

1. 打开 `http://<主机>:<端口>/`。

2. 用刚创建的管理员登录。

3. 登录后能看到主界面，左侧是账号、插件、实例、订单、模拟盘等入口。

4. 右上角确认当前角色为超级管理员。

5. 若开启了二次验证，登录后会要求输入验证码。

## 六、跑通一笔模拟盘交易

### 6.1 第一步：确认插件已加载

1. 进入插件页面。

2. 确认列表中至少有一个插件，状态为已加载。

3. 如果列表为空或存在失败项，点"重新扫描"，再查看失败原因。

4. 正常情况无需任何操作，框架启动时会自动扫描 `plugins/` 目录。

### 6.2 第二步：创建一个账号

1. 进入账号页面，点新增。

2. 若是纯模拟盘验证，可直接使用框架提供的模拟账号入口，不需要真实密钥。

3. 若要接入实盘账号，填写 API 密钥与环境。框架会立刻向交易所验证，通过后才保存，密钥加密存储。

4. 保存后账号状态为正常。若状态异常，去账号详情看失败原因。

### 6.3 第三步：创建实例

1. 进入实例页面，点新建。

2. 依次选择：

| 项 | 选择 |
|---|---|
| 账号 | 上一步创建的账号 |
| 插件 | 已加载的任一插件 |
| 交易对 | 插件支持的交易对 |
| 模式 | 模拟盘 |
| 参数 | 按插件表单填写，留空则用默认值 |

3. 保存后实例状态为"已创建"，此时还没有运行。

4. 参数校验不通过时，会直接提示是哪个字段不合法。

### 6.4 第四步：启动

1. 在实例列表点启动。

2. 状态依次经过"正在启动"，最终变为"正在运行"。

3. 若停在"出错"，进实例详情看最后一条错误。常见原因是账号校验未通过或参数与账号市场不符。

4. 启动后，实例详情页会开始出现行情与日志。

### 6.5 第五步：观察与操作

| 想看什么 | 去哪里 |
|---|---|
| 实例是否在跑 | 实例列表的状态列 |
| 策略在想什么 | 实例详情的日志 |
| 下了什么单 | 实例详情的订单 |
| 持仓与盈亏 | 实例详情的持仓 |
| 净值曲线 | 模拟盘页面 |
| 多实例对比 | 模拟盘的多盘对比 |

可以尝试的操作：

- 暂停与恢复实例，观察日志是否停止与继续
- 手动平掉一个持仓，观察日志里出现保护或人工来源的区分
- 修改一个参数，观察是否触发重新校验

### 6.6 第六步：停止与清理

1. 点停止，状态变为"已停止"。

2. 停止时是否平仓由配置决定，默认保留持仓。

3. 确认不需要后删除实例。运行中的实例不能删除，须先停止。

4. 删除实例会一并清理其模拟盘数据。

## 七、看到什么算成功

逐项确认：

| 检查项 | 期望 |
|---|---|
| `/health` 返回正常 | 服务在跑 |
| 登录成功 | 鉴权可用 |
| 插件列表非空且已加载 | 插件扫描可用 |
| 实例能从"已创建"走到"正在运行" | 引擎可用 |
| 实例日志出现行情回调记录 | 行情分发可用 |
| 模拟盘出现订单与持仓 | 下单路径可用 |
| 模拟盘净值曲线有数据点 | 快照可用 |
| 停止后状态变"已停止" | 生命周期完整 |

全部通过，说明环境、账号、插件、实例、引擎、模拟盘六条链路都通了。

## 九、常见问题

| 问题 | 处理 |
|---|---|
| `/setup` 打不开 | 库中已存在用户，必须由超级管理员在后台指定新管理员 |
| 启动报缺少必需配置 | 检查 `SECRET_KEY`、`ENCRYPT_KEY`、`DATABASE_URL` 是否都填了 |
| 启动报密钥长度不足 | 两个密钥都要 32 位以上，且互不相同 |
| 登录报 401 | 确认用户名密码；连续失败会被锁定，需等待解锁 |
| 插件列表为空 | 确认 `plugins/` 下有插件目录，且目录含必须文件，然后重新扫描 |
| 实例启动就出错 | 查看实例详情的最后一条错误，多数是账号或参数问题 |
| 一直不下单 | 检查参数是否满足交易对精度与最小名义价值 |
| 页面能开但接口全 401 | 登录已过期，重新登录即可 |
| 能不能直接连实盘 | 可以，但要先把 `ENABLE_LIVE_TRADING` 打开并接入真实账号；建议先用模拟盘跑通 |
