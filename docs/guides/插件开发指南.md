# 插件开发指南

> 本文档教如何从零写一个 BAMY 插件并让它跑起来：目录怎么摆、元信息怎么写、参数怎么声明、策略类怎么实现、怎么调试、怎么发布。
> 规则本身见《插件规范》，本文档只讲怎么用这些规则。
> 本文档是完整设计，不是第一版，是最终态。

---

## 一、适用场景

需要新增一个策略时读本文档。包括：

- 新写一个策略插件
- 给已有插件加参数、加能力
- 调试插件为什么加载不起来
- 发布插件给其他人使用

不需要读本文档的场景：只想使用已有插件，见《快速开始》。

---

## 二、前置条件

### 2.1 环境

| 项 | 要求 |
|---|---|
| 运行环境 | Python 3.11 及以上 |
| 框架 | BAMY 已在本机可运行 |
| 目录 | 已存在 `plugins/` 目录 |
| 依赖 | 插件自带的第三方库写进 `requirements.txt` |

### 2.2 心智准备

两条必须先接受的规则：

1. 插件不能直接调交易所，一切下单、查询、持仓动作都通过框架提供的上下文对象 `ctx`。
2. 插件不能直接碰数据库、网络、文件系统与环境变量，框架沙箱会拦截。

违反这两条，插件无法加载或运行即报错。这不是限制，是让插件与实盘、模拟盘、多账号、对账机制自动兼容的前提。

## 三、五步做出第一个插件

### 3.1 第一步：建目录

```
plugins/
  my_strategy/
    plugin.yaml
    strategy.py
    __init__.py
```

目录名就是插件 ID，规则：

- 只允许小写字母、数字、下划线
- 长度 3-32 字符
- 全局唯一
- 不能以 `__` 开头

### 3.2 第二步：写 plugin.yaml

元信息部分：

```yaml
id: my_strategy
name: 我的策略
version: 1.0.0
author: 你的名字
description: 一句话说明适用行情
tags: [spot, futures]
min_bamy_version: 1.0.0
```

参数部分：

```yaml
params:
  - key: order_amount
    label: 每次下单量
    type: float
    default: 10.0
    min: 0.0001
    required: true
    help: 以基础币计价
    group: 基础
```

能力部分：

```yaml
capabilities:
  close_position: true
  cancel_order: true
```

运行配置：

```yaml
runtime:
  tick_interval: 1
  symbols: [BTC/USDT]
```

只声明真正会实现的能力。声明了 `close_position: true` 却没写对应方法，插件会加载失败。

### 3.3 第三步：写 strategy.py

```python
from bamy.plugin import BaseStrategy, StrategyContext


class MyStrategy(BaseStrategy):
    async def on_start(self):
        self.counter = 0

    async def on_tick(self, tick):
        self.counter += 1
        self.ctx.log_info(f"tick {self.counter} price={tick.price}")
        if self.counter % 10 == 0:
            await self.ctx.buy(amount=self.ctx.params["order_amount"])

    async def on_stop(self):
        self.ctx.log_info("stopped")

    async def close_position(self, id, amount=None):
        await self.ctx.close_position(id, amount)

    async def cancel_order(self, order_id):
        await self.ctx.cancel(order_id)


STRATEGY = MyStrategy
```

要点：

- 类名随意，但必须继承 `BaseStrategy`
- 必须导出模块级变量 `STRATEGY`
- `on_start`、`on_tick`、`on_stop` 必须有
- 所有生命周期方法都是 `async`
- 声明了能力就必须实现同名方法

### 3.4 第四步：写 __init__.py

```python
from .strategy import STRATEGY

__all__ = ["STRATEGY"]
```

### 3.5 第五步：加载并试跑

1. 在管理员界面触发一次插件重新扫描。
2. 确认插件出现在插件列表中，状态为已加载。
3. 用调试命令拿模拟行情跑一遍，观察日志：

```
bamy plugin dryrun my_strategy --symbol BTC/USDT
```

4. 确认日志里 `on_tick` 正常触发，没有异常计数增长。
5. 创建一个模拟盘实例挂上该插件，观察净值曲线是否符合预期。

## 四、参数怎么写

### 4.1 支持的类型

| type | 说明 | 可配字段 |
|---|---|---|
| `int` | 整数 | `min` `max` `default` `required` |
| `float` | 浮点 | `min` `max` `default` `suffix` |
| `bool` | 布尔 | `default` |
| `string` | 字符串 | `default` `max_length` `pattern` |
| `select` | 单选 | `options` `default` |
| `multi_select` | 多选 | `options` `default` |
| `symbol` | 交易对 | `default` |
| `timeframe` | 周期 | `default` |

### 4.2 字段含义

| 字段 | 说明 |
|---|---|
| `key` | 参数键，策略里用 `ctx.params["key"]` 读 |
| `label` | 界面显示名 |
| `type` | 类型 |
| `default` | 默认值 |
| `min` / `max` | 数值范围 |
| `required` | 是否必填 |
| `help` | 字段说明 |
| `suffix` | 单位后缀，如 `%` |
| `group` | 分组名，界面按组展示 |
| `options` | 枚举项，每项含 `value` 与 `label` |
| `depends_on` | 条件显示，含 `key` 与 `value` |

### 4.3 写参数的规矩

- 每个参数都要有 `label` 与 `help`，界面才不会出现只有键名的字段
- 有范围的数值一定写 `min` / `max`，这是框架前置校验的依据
- 互斥或联动的参数用 `depends_on` 声明，不要靠策略内部判断
- 用 `group` 把参数分到基础、高级、风险这类组里，参数多时界面才不至于一屏塞满
- 默认值必须是一个能跑起来的值，不要留空等用户填

## 五、能力与实现的对应

| 能力声明 | 必须实现的方法 | 触发场景 |
|---|---|---|
| `close_position` | `close_position(id, amount)` | 用户点平单仓 |
| `close_positions` | `close_positions([ids])` | 用户点平多仓 |
| `close_all` | `close_all_positions()` | 用户点一键全平 |
| `close_partial` | 在 `close_position` 中支持 `amount` | 用户填部分数量 |
| `cancel_order` | `cancel_order(order_id)` | 用户撤单 |
| `cancel_all` | `cancel_all_orders()` | 用户撤全部 |
| `set_leverage` | `set_leverage(n)` | 框架或用户设置 |
| `set_margin_mode` | `set_margin_mode(mode)` | 框架或用户设置 |
| `set_position_mode` | `set_position_mode(mode)` | 框架或用户设置 |
| `list_positions` | `list_positions()` | 查看持仓 |
| `pause` | `pause()` | 用户点暂停 |
| `resume` | `resume()` | 用户点恢复 |
| `reset` | `reset()` | 用户点重置 |

不声明就不必实现，框架会隐藏对应按钮。

`list_positions()` 返回值必须包含稳定 ID、交易对、方向、数量、开仓均价、标记价、未实现盈亏。ID 在持仓存续期间不能变，否则用户的平仓操作会指错对象。

## 六、生命周期与约定

### 6.1 调用顺序

```
加载插件 → 实例化策略 → 注入 ctx → on_start()
   → 订阅行情 → on_tick(tick) 反复触发
   → （暂停时 on_pause()）→（恢复时 on_resume()）
   → 用户点停止 → on_stop() → 取消订阅
```

### 6.2 必须知道的约定

- 同一实例的方法调用是串行的，不会并发调用 `on_tick`
- 策略抛出的异常由框架捕获、记日志、计数，连续超过阈值自动停止实例
- 异常不向上传播，一个实例出错不影响其他实例
- 策略内部耗时的操作必须 `await`，否则会阻塞该实例的调度
- `on_start` 抛异常 → 实例启动失败，状态置为出错
- `on_stop` 抛异常 → 记日志，仍视为停止成功

### 6.3 状态怎么保存

用 `ctx.state` 存实例级键值对，进程重启后仍在，用来"接着跑"：

```python
await self.ctx.state.set("last_grid_level", 3)
level = await self.ctx.state.get("last_grid_level")
```

不要用类属性保存跨重启的状态，类属性在重启后丢失，并且会被同一插件的其他实例共享。

## 七、调试与排错

### 7.1 常用手段

| 手段 | 用途 |
|---|---|
| `ctx.log_info` / `log_warn` / `log_error` | 在实例日志里留下痕迹 |
| `bamy plugin dryrun <id> --symbol <交易对>` | 用模拟数据跑 `on_tick`，不产生真实下单 |
| 模拟盘实例 | 验证完整下单路径与净值曲线 |
| 实例详情页的连续错误计数 | 判断是否触发自动停止 |

### 7.2 加载失败的常见原因

| 现象 | 原因 |
|---|---|
| 插件不在列表里 | 目录以 `__` 开头，或目录名不符合命名规则 |
| 提示缺少必须文件 | 少了 `plugin.yaml`、`strategy.py` 或 `__init__.py` |
| 提示未导出 STRATEGY | `__init__.py` 没有导出 `STRATEGY` |
| 提示能力不匹配 | 声明了能力但没实现对应方法 |
| 提示参数校验失败 | 参数缺少必填字段，或 `type` 不被支持 |
| 解析元信息失败 | YAML 缩进错误，或 `id` 与目录名不一致 |

### 7.3 运行时的常见原因

| 现象 | 原因 |
|---|---|
| 实例启动即失败 | `on_start` 抛异常，或前置校验未通过 |
| 实例跑一会儿自动停 | 连续异常超过阈值，去看实例日志的最后几条错误 |
| 下单一直不成交 | 数量或价格精度不合法，或名义价值低于交易所最小值 |
| 平仓按钮点了没反应 | 未声明对应能力，或声明的能力没有实现 |
| 重启后策略行为异常 | 关键进度存了类属性而不是 `ctx.state` |

### 7.4 热更新的限制

- 插件代码被重新加载时，已运行实例不会自动换用新代码
- 需要人工停止再启动实例才会生效
- 新代码加载失败时，框架保留旧版本继续运行

## 八、安全边界

### 8.1 不能做的事

- 直接 import 交易所库
- 直接访问网络
- 直接访问数据库
- 读写其他实例的上下文
- 读环境变量
- 写插件目录以外的文件
- 使用 `subprocess`、`eval`、`exec`

### 8.2 为什么

插件代码是用户可见、可替换的。沙箱保证一个插件的行为不外溢到别人的数据和其他实例，也让插件在实盘与模拟盘之间自动通用。

### 8.3 违规的后果

| 行为 | 结果 |
|---|---|
| 导入白名单之外的模块 | 加载失败并记录原因 |
| 运行期触碰被拦截的操作 | 抛异常，计入连续错误计数 |
| 反复违规 | 实例被自动停止，事件记入审计 |

## 九、发布

### 9.1 版本规则

- 用语义化版本：不兼容变更升主版本，新增功能升次版本，修 bug 升补丁
- 主版本变更须在说明里写清不兼容点
- 声明 `min_bamy_version`，避免在不支持该插件的框架上运行

### 9.2 发布内容

| 文件 | 必须 |
|---|---|
| `plugin.yaml` | 是 |
| `strategy.py` | 是 |
| `__init__.py` | 是 |
| `requirements.txt` | 有第三方依赖时 |
| `README.md` | 是，说明适用行情、参数含义、风险提示 |

### 9.3 兼容性检查

发布前逐项确认：

1. 所有声明的能力都有实现
2. 所有参数都有 `label`、`help`、合理的默认值
3. 在模拟盘上完整跑通启动、下单、平仓、停止
4. 连续运行一段时间，错误计数保持为零
5. `README.md` 里写清了风险与适用边界

## 十、常见问题

| 问题 | 回答 |
|---|---|
| 插件能直接调交易所下单吗 | 不能，必须走 `ctx`，否则实盘与模拟盘无法共用同一份代码 |
| 一个插件能同时支持现货和合约吗 | 能，通过 `runtime` 与参数声明，运行时由实例的账号决定实际市场 |
| 插件能自己画界面吗 | 能，放进 `static/` 目录，但表单仍以参数声明为主 |
| 参数改了会不会影响正在运行的实例 | 修改参数会触发实例的重新校验，具体见《实例模型设计》 |
| 插件能调另一个插件吗 | 不能，插件之间不互相调用，共用逻辑应各自实现或放进插件自己的 `helpers/` |
| 要不要写单元测试 | 要，纯计算部分可以脱离框架测试，涉及 `ctx` 的部分用模拟盘验证 |
